### 两条线的调仓频率不同 —— 同一天不一定都调仓

| 线 | 频率 | 判定 |
|---|---|---|
| 红利指数增强 | **月频** | 每月第 1 个交易日（`run_monthly(..., 1)`） |
| FROEC-TRADED | **周频** | 每周第 1 个交易日（`run_weekly(weekday=1)`，通常周一） |

例：2026-09-01（周二）是 9 月第 1 个交易日 → **红利调仓**；
但本周第 1 个交易日是 08-31（周一）→ **froec 不调仓**，下次 09-07。
两个 preview 都会自己判并打出来。

> `run_weekly` 锚在**自然周**上：假期短周会让实际间隔在 1~13 个交易日之间跳
> （本地实测 `weekday=1` 有 15 次间隔 ≤2 天）。这是原版行为，不是 bug。

### 🔴 FROEC-TRADED：`traded` 这条规则样本外已否证

本地实测 2006-01~2015-12（默认成本，10 万）：

| | 年化 | 回撤 | 夏普 |
|---|---|---|---|
| A（JQ 原版口径，宇宙含停牌股） | **83.06%** | 51.94% | 1.91 |
| B（`traded` 宇宙） | 74.20% | 54.35% | 1.76 |

**−8.86pp**，B 在 8/10 年落后（2007 差 −83.8pp、2006 −23.2pp、2014 −15.0pp），
且 B 仓位更高（91.7% vs 89.5%）却赚更少。对照样本内 2016-2026 的 +1.87pp
—— **符号翻转**。

所以 `froec_traded.py` 里 `TRADED_UNIVERSE=True` 是为了**对标标星那次**，
不是因为它更好。改成 `False` 就退回 JQ 原版口径，**值得一起跑做对照**。

### FROEC 的祖本选 v3 不是 v6

`JQ/小市值/FROEC-PB-CAP-HL-v6.txt` 把 ROE 因子换成**扣非 TTM ROE 同比增长**，
而本地标星用的是**5 期单季 ROE 的 increase 公式**：

```
increase = 4*roe(最新) - roe(前4期之和)
```

与 v3 的 `4*df.iloc[:,4] - df.iloc[:,0..3]` **逐字一致**。
v6 自己的 changelog 也写着 v4（单季同比）26.24%、输 v3 4.41pp。

## 为什么要有 `check.py`

关联写成注释是**留不住**的：本地策略一改、标星一换，注释还在那儿，人却不会去改它。
所以 `LOCAL_PORT` 是**断言**。反向验证过四种改法都会红：
改 `run_id` / 改 `params` / 改 `cash` / 改 `metrics`。

`selftest.py` 里有一条用例跑它，所以链接烂掉会在测试里暴露。

## 🔴 成本必须对齐，否则数字不可比

`COST_MODE = 'align_local'`（本文件默认）逐项复现本地标星那次回测：

| | 本地标星 | JQ 平台默认 |
|---|---|---|
| 佣金 | **0.00025**（万2.5） | 0.0003（万3） |
| 最低佣金 | 5 | 5 |
| 滑点 | **0.0015** | 0.00246 |
| 印花税 | **分段**：2023-08-28 起 千1 → 万5 | 固定千1 |
| 成交量比 | **0.25** | 平台默认 |

印花税那条最容易漏：JQ 的 `set_order_cost` 是一次性的，要靠 `run_daily` 每日盘前
重设才能复现本地的 `close_tax='auto'`。**不做这一步，2023-08-28 之后本地卖出税只有
JQ 的一半** —— 年双边换手 8.4 次，千1 vs 万5 的差约 **0.42%/年**，正好落在噪声底
附近，很容易被误读成策略差异。

另两档：`'jq_default'`（复现 JQ 平台默认，用于验收 A-2）、`'account_real'`（实盘费率）。

## 盘前预览：`hongli_preview.py`

**研究环境（Jupyter）跑，不是回测。** 在回测里跑会取到回测日期之后的数据 = 未来函数，
脚本自己会检测并报警（实测踩过一次：日志显示 2019-01-01，而价格是 2026-08-31 的）。

为什么能在 T 的 00:00 之后就算：选股全部用 `context.previous_date` 的数据
（财务 as-of、分红 `board_plan_pub_date <= T-1`、beta 到 T-1），对交易日 T 来说
输入在 00:00 就已确定。唯一用到 T 当天信息的是价格 —— 限价按 T-1 收盘 ×1.05 估
（与回测版 `buy_df['price']` 同算法），所以**数量是估算**。

改三处：`TRADE_DATE` / `HOLDINGS` / `CASH`。持仓三种写法都认，可混写：

```python
HOLDINGS = {
    '招商银行': 2000,        # 按名称（用 T-1 那天的名称）
    '601398': 10000,        # 六位代码，自动补后缀
    '600519.XSHG': 100,     # 完整聚宽代码
}
```

解析不了的会**明确报出来**，不静默丢 —— 静默丢一只等于那只永远不会被卖。

### 🔴 `BUY_ALLOC`：三种分配口径，实盘差别很大

以 15 只目标、可用 54.35 万、其中一只是高价股（一手 13.65 万 > 每份 10.87 万）为例：

| 口径 | 四只买入金额 | 最大/最小 | 剩余现金 |
|---|---|---|---|
| **`twopass`（默认）** | 135759 / 136141 / 134190 / 135096 | **1.015** | 2,314（0.4%） |
| `fixed` | 108147 / 108663 / 107352 / 107384 | 1.012 | **111,954（20.6%）** |
| `seq`（JQ v7） | 108147 / **144884** / 144627 / 145488 | **1.34** | 354 |

- `fixed`：买不进的那份**闲置** → 20.6% 仓位拖累
- `seq`：买不进的份额**流给后面** → 后面超配 34%。而**方向不中性**：
  前面是 Sleeve A（低波），后面是 Sleeve B（价值，单跑回撤 29.47% vs 低波 17.92%）
  —— 系统性把权重挪向高风险腿
- **`twopass`**：先按 `cash/n` 预分配，买不进的不占份额，剩余（含那份 + 取整残差）
  平分给已建仓的补仓 → **权重不漂、现金不闲置**

> **本地回测里三者差异 ≤ 0.03pp 年化**（10.5 年）：`fixed` 20.07%/17.95%/夏普1.30、
> `seq` 20.10%/17.78%/1.31、`twopass` 与 `fixed` **逐位相同**。
> 原因在拒单明细里：「资金不足一手」10.5 年 126 次调仓**只发生过 1 次**，
> 平均仓位 99.4%，第二轮基本不触发。
>
> **但历史罕见 ≠ 现在无所谓** —— 高价股（如茅台一手 13.6 万）近年才进入红利池，
> 而 100 万 / 15 只 = 6.67 万/只。**根本约束是一手门槛，不是分配算法**：
> 任何算法都买不进茅台，区别只在那 6.67 万怎么处理。

本地策略同样加了 `--param buy_alloc=fixed|seq|twopass` 可对照，默认仍是 `fixed`
（归档标星那次用的口径，改默认会让 `check.py` 的指标断言失配，而收益逐位相同）。

## 三条无法消除的实现差异（对账时算进容差）

1. **beta**：本地自算（`std/beta_daily.parquet`，沪深300 252 日滚动回归），JQ 用
   `get_factor_values`。对齐区间本金后 红利低波 差 **+0.05pp**。
2. **炸板离场**：JQ 在 10:00 取那一刻的**分钟价**，本地只有日线，用「今日是否仍收在
   涨停价」代替（尾盘决策）。小市值线实测这个代理值 **0.3~1.0pp**。
3. **股本生效时点**：tdx 比聚宽**晚 1 个交易日**，边界日选股可能差一只，本地无法消除。

## 选股逻辑：逐条核过，一致

`LOCAL_PORT['aligned']` 里有 15 条对照。A-6（fiscal_year）的四条规则逐条比过：
可见性键 `board_plan_pub_date`、回溯 800 天、去重键 `(code, report_date, bonus_type)`、
阶段序 实施方案3/股东大会预案2/董事会预案1/其它0、年度锚定 `report_date` 月份==12。

唯一形式差异：本地去重时多加了 `board_plan_pub_date DESC` 作第二排序键（JQ 用
`keep='last'` 依赖 DataFrame 原顺序）。实测**同一 `(code, report_date, bonus_type,
plan_progress)` 有多条的组数 = 0**（53,712 组里 0 组），所以第二键永不触发，两边等价。
