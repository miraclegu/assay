# 实盘与模拟盘 —— 踩坑详情

正本索引在 `assay/CLAUDE.md`。**改 assay/lv/ 或实盘页之前**读这一册；里面每一节都是实测定案（有现场、有判据、有变异结果）。

## 🔴 首页只列真实盘 · 当日盈亏 · 手工账户是一等状态（2026-09-19）

用户另外两条：「首页只需要展示真正的实盘，模拟盘不展示，并且能把当日涨跌
金额、幅度展示出来，替代掉持仓的浮盈」「策略账户增加一种非策略账户，
无需绑定策略」。

**首页**：`filter(a => !a.archived && !a.paper)` —— 判据用服务端给的 `paper`
（`lv.is_paper` 唯一定义），不在前端比 `mode` 字符串（老账户没有那个字段）。
理由：首页回答"今天什么状态、要做什么"，而模拟盘是**推演** ——
混进来会让待办里出现"引擎明天要买什么"这种其实不用你动手的事。
★ 「持仓浮盈」换成「当日盈亏」：首页问的是**今天**，而浮盈是开仓至今的
  累计（那是复盘，属于业绩页）。幅度的分母是**持仓市值**，与实盘页那一格
  同口径，所以小字要标"持仓"（不标的话同屏两个百分比看着像有一个算错了）。
★ 空态也要改：可能"有模拟盘但没实盘"，那时要说清模拟盘为什么不列。

**非策略账户**：🔴 **不加字段**。`code_sha256` 的有无已经是这个状态的唯一
真值，加一个 `no_strategy` 就是第二份状态，而"标了却绑了策略"之类的组合
迟早出现且分叉不报错。要改的是**怎么说它**：

    改之前  待办区「还没有信号 —— 点「立即重算」」+ 一个按钮
            而点下去必然报"账户还没绑定策略" —— **指向一条走不通的路**
    改之后  「这是手工账户 —— 不跑策略，所以没有信号与待办」
            + 一句"持仓/成本/收益/业绩页都照常用，成交自己录"
            + 一个「绑定策略 ›」入口（想绑随时能绑）

★ 顶栏那个标签也从「未绑定策略 ›」（缺失态）改成「手工账户」+「绑定策略 ›」。
★ 两个「绑定策略」入口走**同一条链**（`openStrat`）—— 各写一份迟早
  一个能开一个不能（同 `paperRebuild` 那条）。

★ 判据落在**可量的事实**上：首页列出的账户集合 == 服务端说的非模拟盘集合
  （不是"少了两行"）；那一列的数 == `pos.pnl_day`；手工账户页上
  **不许有**「立即重算」那个按钮（它点了必然报错）。9 条变异全抓到。

🔴 **第四次**在 HTML 注释里写反引号，当场把模板闭合掉 —— 而上一轮刚把
  `node --check` 钉成判据，这次就是它抓到的。**守卫值回票价了。**

★ 顺带打挂一条既有断言：「总览首页」那条钉的是**列名「持仓浮盈」** ——
  而换掉它正是这次要做的事。**失败的是断言不是产品**，但它保的
  "不是空壳"不能丢：改成钉新列名 + **真的列出了账户行**
  （只查文本的话，表头在、一行都没有也算过 —— 同「页签点得开 ≠
  页签里有东西」那条）。

## 🔴🔴 公司行动：除权之后【成本必须跟着调】（`assay/lv/corp.py`，2026-09-23）

用户："分红后，没有将分红的金额相对应的折算扣减成本，比如平安、吉比特，
分红后现金增加，对应的股的成本也应该降低" -> "这肯定要动成本，为什么不动
成本？股价已经除权了，成本不除权？" -> "不仅仅是分红，如果有拆股等等，
都要能正确的计算价格、股数……c1~c4 的含义需要记录下来，不要每次去猜。"

实测红利混合-M 三次除权合计 **3,560 元**（占权益 0.36%）：

    2026-09-10 601318 派现 0.98/股 × 1100 股 = 1,078
    2026-09-16 601857 派现 0.26/股 × 5700 股 = 1,482
    2026-09-17 603444 派现 10.00/股 × 100 股 = 1,000

🔴 **最难发现的一种：总资产那一格没毛病，逐只浮盈全错。** 现金那半在券商
那边加回来了，股价那半掉下去了，人只会觉得"这只票怎么跌了"。

### 🔴🔴 我第一版答"不该动成本"，那是把两个口径搞反了

我引的是 `broker.py` 那句「entry_price 在除权时不缩」——**那是后复权语境**：

    后复权（回测）   除权日价**不掉** -> 成本不动是对的（分红以"价格上涨"体现）
    不复权（账本）   除权日价**掉了** -> 成本必须跟着调，否则两边不自洽

**两条的分工别记反。** 用户一句"股价已经除权了，成本不除权？"就点破了。
★ 回测**没有**这个问题，这是量过的：`dividend` 表缺行只有 52/35,621 = 0.15%，
  而 hfq 价里已经含着那笔分红，总权益仍然对。

### 数据源取 tdx `gbbq`，不取聚宽 `dividend`

`std/dividend.parquet` 走 B 腿（**手动导**），而复权因子随 cron 每天到 ——
于是「因子跳了而分红表里没有那一条」（601318 实测差 486 元）与它的反面
（002293 分红表有、因子没跳）**两个方向都有，且都不报错**。
gbbq 每天自动到（实测提前 4 天覆盖除权），而且**带送转与配股**。

新增 `datalake/build/load_tdx_gbbq.py` -> `raw/tdx/gbbq.parquet`
（`sync_daily.sh` 的 **10/12**，链从 11 步变 12 步）。
c1~c4 的含义、category 表、通用除权公式与自证全写进**数据字典**
（索引 1 / 3 / 4 各一处）—— 用户明确要求"不要每次去猜"。

🔴 **自证是「拿通用除权公式复算 `hfq_factor` 的跳变」**：35,621 个样本
平均误差 **0.000000000**、超差 0 条，不过就**拒绝写出**（退出码 2）。
反向验过：漏掉送转那一项 -> 平均误差 **0.0716** -> 当场拒绝。
★ 所以 loader 每次跑都重算一遍这个自证（同「交易日历每次生成都重跑对数」）。

### 🔴 只动【股数与成本】，`lot['price']` 一个字不动

`price` 要 × **建仓日**因子喂给引擎的 `entry_price`（止损/吊灯/红利税档位
都读它）。所以每批多两个字段：

    paid       该批剩余部分的**实付本金**。派现减它、送转不动它
    div_gross  累计收到的税前分红（红利税按批定档要用）

摊薄成本 = `(paid + fee) / shares` —— 派现降 paid、送转涨 shares，两种都自动对。
★ **A/B 量过**：`cost_net` 恰好降 c1（0.98 / 0.26 / 10.00 三只**逐分**对上），
  `cost`（成交均价，引擎口径）**一个没动**，另外 6 个账户**逐位相同**。
★ `sig._seed` 那条路不用改：它是 `shares / factor(今天)`，送转让两边同步放大，
  **自己抵消**。

### 🔴 三处"改一处之前先扫同类"，漏一处就是另一个静默错值

| 处 | 不改的表现 |
|---|---|
| `cash()` | 少 3,560 元 |
| **`cash_asof()`**（另一份实现） | 权益曲线在除权日**掉一截**（市值跌了、现金没回来），看着像"那天亏了" |
| **`lots_asof()` 没把 `asof` 传下去** | 历史某天的持仓被"那天之后才发生的除权"调过 —— **未来函数**，而 equity_curve / hist / sig._replay 三条路都走它 |

### ⚠ 三条明知的取舍（不是漏掉）

1. **税不自动扣**：A 股红利税是**卖出时**按持有期补扣的，那笔钱会出现在
   卖出成交的费用里 —— 照账单录进去就已经扣过，这里再扣就是双计。
   所以现金按**税前**加，与券商到账口径一致。
2. **到账日按除权日算**：gbbq 只有除权日。差一两天对成本与浮盈没有影响
   （两边同一天调）。
3. 🔴 **配股不自动执行**：送转与派现是**强制**的，而配股**要掏钱、可以放弃**
   —— 替人决定就是错的。所以它只**留痕 + 提示**（同「报出来，别替人决定」）。
4. 手工录过 `dividend` 流水的账户**不自动加**（双计），并由 `corp_conflict()`
   把冲突说给页面听 —— 不替人合并、也不静默二选一。

### ★ 留痕：持仓表下面一行，不新开一块

用户第三条要求。`lvCorpNote(P)` 逐条列「除权日 / 名称 / 每股派现或送转 /
这本账实收多少 / 股数前后」，另加三件：
**数据落后**要说（落后的表现是"这几天除权的不会被调"，不报错）、
**即将除权**预告（gbbq 里有 129 条已公告未除权）、**撞车**提示。
🔴 什么都没发生时**整块不渲染** —— 常驻一条"一切正常"等于教人忽略这个位置。
★ 落后/撞车走 `lvwarn`（要人去做事），已发生与预告走 `lvwhy`（只是解释）
  —— 警告不许混进解释里。

### 🔴🔴 留痕的形态：横排铺开 -> 一行摘要 + 一个页签（2026-09-24 第二版）

用户："公司行动在下面横排用小字显示，如果行动项很多的话可能会排列有点拥挤，
再考虑下有没有其他的实现方式。"—— 成立。v1 是
`ev.map(...).join('　·　')`，持有一年十几二十条分红那一行会**绕成好几排**，
而且**没法纵向扫**（同「要横向比较 N 条东西，就得是表格，不能是卡片」）。

v2 拆成三处，**各自回答一个问题**：

| 问什么 | 放哪 |
|---|---|
| 这只票的成本为什么低了 | 持仓行名称后一个 `⊙`，hover 给**这只票**的（同「备注不占一列，名称后带 ✎」） |
| 一共派回来多少现金 | 持仓表下**一行**摘要 —— 条数再多也只有一行 |
| 完整历史 / 已清仓的那些 | 业绩页**「公司行动」页签**的表格（插在盈亏榜与选股理由之间） |

★ 「会越来越长的复盘信息都归业绩页」是**已确立的模式**（成交流水与选股理由
  2026-09-22 就是这么并进去的），所以第 9 个页签不是新发明。
🔴 摘要那一行**必须带入口**（`?tab=corp`），否则"收起来"就等于把明细藏起来
  （同「合并的风险不是少两个按钮，是把功能藏起来」）。
🔴 `⊙` **刻意不描成 `.lvq` 那样的圆圈按钮**：`.lvq` 是可点的（跳选股理由），
  而这个只是 title 提示 —— 画成一样的话人会去点它，**而它点了没反应**。
★ 明细页比摘要多的正是两样：**已清仓的票也在**（它在除权那天还持有着，
  而持仓表里早没有它了）、**股数前后**（送转是 `1000 → 1480`）。
★ 名称在**服务端**补（`px.names_of` 正本）—— 页面拿"当前持仓"去配是配不上
  已清仓那几只的，屏幕上就只剩一串代码（同「ETF 那一列空的」）。

#### 🔴🔴 顺带逼出【第四份重放】：送转之后卖出会被【误拒】

构造「送转 1480 股之后全卖掉」时当场报：

    LiveError: 这笔卖出会让 688399 在 2026-09-02 的持仓变负：
               当时只有 1000 股，要卖 1480 股

`replay_violation` **自己数了一份** `held[code] += / -=` —— 那是第四份重放，
**不认识公司行动**。于是券商账户里真有 1480 股，照实录一笔卖 1480 却录不进去，
**而那句报错还指不到真正的原因**（人会以为自己股数记错了）。

🔴 上一轮「改一处之前先扫同类」扫出了三处（`cash` / `cash_asof` /
`lots_asof`），**漏了这一处** —— 因为它不调 `fifo_lots`，按调用去 grep
找不到。**判据要按【语义】扫（"谁在重放账本"），不是按调用扫。**

修法是把违规判定**并进 `fifo_lots` 本身**（`viol=` 收集），
`replay_violation` 只剩一句转发 —— 重放从此只有一份。
★ 判据**两头都要**：送转后卖 1480 必须放行 **+ 清仓之后再卖必须仍被拒**
  （只测前者的话"永不拒"也全绿 —— M11 变异实测）。

### 🔴 送转与配股在真实账本里【一条都没有】—— 那两条路必须构造

34 只持仓票在窗口内只有 **3 笔现金分红**，送转 0、配股 0。
所以判据拿**真实的历史事件**当夹具（并反向自证夹具还在）：

    688399.XSHG 2026-07-10  纯送转 0.48/股      -> 1000 股必须变 1480
    001388.XSHE 2026-07-17  派现 0.50 + 送转 0.48 -> 验"先派现后送转"
    300176.XSHE 2026-08-21  配股 0.40 @ 3.36     -> 股数**不许**变，但要留痕

🔴 **同一天：先行动、后成交。** 分红归**登记日收盘**（= 除权日前一天）的
持有人 —— 除权日当天**买入**的拿不到，当天**卖出**的拿得到。写反了两种都错。

★ **12 条变异全抓到**，其中两条第一轮漏了，都是我自己的判据问题：

| 漏的 | 为什么 |
|---|---|
| 「`price` 不许动」 | 我钉在 688399 上，而**那只没有派现**（c1=0）—— `price -= cash` 对它是空操作。改钉在真收到过现金的那一批上（**判据比要证的事窄**） |
| 「部分卖出按比例缩 paid」 | 构造里**只买不卖**，那条路一步都没走到。补了一笔卖 740 股（同「断言要在能触发的构造上跑」） |

### 🔴🔴 第三条打挂的**是产品**：我把一个既有竞态的窗口撑宽了

全量跑出 149/150，唯一那条「推进完 0 笔成交」**可复现**（35 秒超时）。
现场是这样的（**打出来才看清，前两次我都在猜**：先猜性能、再猜选择器，
实测 `positions_valued` 只要 0.19 秒，两次都猜错）：

    hash = #/live          #nf_paper **在**
    nform 个数 = 0         .nc 的值 = None      <- 表单整块被清空了

—— 正是记过的那条「侧栏整块 innerHTML 重渲染，点击落在将被替换掉的 DOM 上」。
而它此前**只是 7.5% 的偶发**，我这一轮把它变成了必现：`positions_valued`
里 `corp_summary` 调了两遍 `fifo_lots`、`corp_conflict` 又一遍、`cash()` 再一遍，
加上 **20 条 duckdb 查询、每条新建一个连接**（实测 0.75 秒）——
那点开销自己不报错，只是把窗口撑宽到必中。

收窄回去三条：① `corp.actions` 按 **(文件 mtime, 代码集合, 区间)** 缓存；
② `corp_summary` **一次重放拿两样**（事件 + 持仓）；

  瞬填表单同样会被清掉 —— 那是另一轮的事（CLAUDE.md 里本来就记着）。
  我做的只是**别再往那个窗口里加东西**。
🔴 缓存又差点写成「miss 就 `clear()`」—— 那样一轮渲染里每个账户的代码集合
  都不同，缓存最多只留一项，**等于没有**。这个错本项目两轮里已经犯过两次
  （`srv/factors._SUM` 与 `factor_eval._PQ`），第三次是靠"写之前先想一遍"
  才没犯。**逐键各记各的 mtime。**

### ★ 打挂两条既有断言，都是「失败的是断言不是产品」

## 实盘模块（live）

`python3 serve.py` → 顶栏「💰 实盘」。**默认就是全功能**（2026-09-04 改）。

🔴 **原来 `--live` 与 `--allow-backtest` 两个开关都默认关,已废除**。
理由是"有副作用的部分放在开关后面",但自用项目下它制造的问题更大:
- 实测踩过:忘了加 `--allow-backtest`,网页上「用这个版本跑一次」渲染成
  **disabled** —— **点了没反应,而 disabled 的元素连 title 提示都不触发**,
  完全无法自查(同 backLink 那条:给一个点了没反应的按钮比不给更糟)。
- 实盘是这个看板的主要功能,`--live` 事实上每次都要加;两个开关里总有一个忘,

## 🔴 「是不是调仓日」不能从【委托】反推(2026-09-07)

`lv/sig.py` 里原来写的是 `is_rebal = bool(rebal_orders)` —— 从"策略下了几个
调仓委托"反推。于是调仓日**什么都不用动**时(目标池恰好等于当前持仓)策略一个
委托都不下 → 判成"今天不是调仓日" → 页面把下次调仓说成一周后。

★ 原版下**永远不暴露**:调仓日总会卖掉几只(黑名单剔除、排名掉出),
`rebal_orders` 从来不空。开 `lu_buy_only=1` 之后第一次出现"调仓日零委托",
这个 bug 才现形。
★ 与「调仓日的'持有不动'从**委托**反推」是**同一个根因**的另一半 ——
那次修的是清单,这次是"是不是调仓日"本身。**判据要问日历,不要问策略做了什么。**

🔴 顺带加固了一个静默错值:`Engine._build_ordinals` 只覆盖
`feed.trading_days`,而实盘问的正是**下一个交易日**(它没有行情、不在面板里)。
`_due` 对表外日期取 `(0, 0)` → 与任何 weekday 都不等 → **静默返回 False**,
也就是静默说"今天不是调仓日"。现在 `is_rebalance_day` 在这种情况下**抛错**
(调用前必须先 `_extend_ordinals`)—— 宁可报错,也不给一个看着正常的 False。

#### 🔴 切副图"闪一下"：`reloadInd` 无条件重建了三块跟指标无关的 DOM

用户："个股里切换副图时，整个页面会闪一下。这种局部切换图、数据的都不应该
刷新整个页面。"

查下来 `load()` **一次都没被调用**、`#body` 也没重建（那条既有断言是绿的）。
真正被 `innerHTML` 整块换掉的是另外三块：工具条（⚙设置 + 主图开关）、
槽位层（下拉框 + ⚙ + ×）、「+ 副图」那一行 —— **换一个副图指标时，这三块
没有一块跟着变**。代价是**用户刚点的那个 `<select>` 被销毁重建**：焦点没了、
原生控件重绘，屏幕上就是闪一下。

现在按块分工重建，判据也按块分工钉（同实盘页 quiet/全量那条）：

| 动作 | 只许动 |
|---|---|
| 换副图指标 | **一个控件都不许重建**（只重画画布） |
| 主图开关 | 工具条 |
| 加 / 删副图 | 槽位层 + 「+副图」行（`data-j` 要重排，非重建不可） |

🔴 **签名要从 DOM 读，不要另存一份"上次渲染成什么样"。** 首屏那几块是
`load()` 里拼模板直接吐出来的、根本不经过 `reloadInd` —— 存变量的话初值
永远不等，于是**每次打开页面的第一次切换照样整块重建、照样闪**。实测踩过。
从 DOM 读则不需要任何地方"记得同步"（同「判据永远是现在的状态，不是记录」）。
★ 比 `KMAIN` 时**两边都要排序**：它是点击顺序，而 DOM 按 defs 顺序渲染 ——
  不排的话 `['boll','ma']` 与 `'ma,boll'` 永远不等，等于没有这个判据。
★ 既有那条断言只钉了 `#kcv` 没被换 —— **判据比要证的事窄**，所以它一直是
  绿的。补成"这三块里每个元素都不许重建"。

#### 🔴🔴 第三次报"还是跳" —— 剩下的三个来源，都不在 DOM 结构上

用户："切换附图时还是会明显感觉跳动一下，体验不好。"
前一轮修的是"DOM 被重建"，而逐帧量下来那一条确实已经干净了：
**整页每个元素 242 帧位置零变化、屏幕帧的像素差只落在副图那一块**。
所以剩下的三个来源都在别处 —— 而且没有一个会报错：

**① 等接口的那几百毫秒。** 点完下拉框，旧图还杵在那儿，回来才"啪"地换成
新图。**那个突变就是跳动感**。实测：取全部 10 个副图 + 主图共
**47.6 KB / 29ms**，只取 2 个是 13.4 KB / 28ms —— **几乎一样快**
（开销在建面板，不在算哪几个指标）。所以一次全取、缓存住（`KIND_CACHE`），
切换时**零请求、下一帧就换**（实测 9~13ms）。
★ 与指标广场那条「分页只取当前页」**不冲突**：那边是上百个指标的场景，
  这边副图统共十来个。**判据不同是因为量级不同**。
🔴 首屏那一份也要**进缓存** —— 它走 `load()`、不经过 `reloadInd`，
  不存的话"第一次切换"必然 miss（实测 59ms vs 之后 8ms）。
  同「签名从 DOM 读」那条的教训：**首屏那条路和交互那条路要在同一个状态上会合**。

**② `load()` 一进来就把 `#body` 换成「加载中…」** —— 高度**先塌陷再撑开**。
而「区间 / 复权」这几个按钮就挨着副图的下拉框，点它们同样整页塌陷一次。
实盘页早就为这条改过（`livePatch`，「刷新只换数字，不许重建 DOM」），
**个股页一直是老样子**。现在已经有画布时就不清空，只在那行常驻提示位上
写一句「更新中…」（它不改变任何元素的高度）；首屏仍然给「加载中…」。

**③ 改参数时整个弹窗被重渲染** —— 输入框失焦、光标位置丢失，想连着改两个
参数得重新点一次。而且销毁正聚焦的元素会让那次 `innerHTML` 赋值**直接失败**
（`Failed to set the 'innerHTML' property … Perhaps it was moved in a 'blur'
event handler?`），只在控制台里报。现在"焦点在弹窗里"就跳过重渲染。

##### 🔴🔴 blur 补发的 change 把刚删掉的参数又写了回去

修好 ③ 之后「恢复默认参数」挂了，而**控制台一个字都不报**。逐层加日志才
定位到时序是反的：

    KPWRITE t=5776 v=19     <- 点 kprst 时 blur 补发的 change，先到
    RST START t=5780        <- click handler 后到，这才去删 KP

浏览器在输入框失焦 / 被销毁时会**补发一次 change**，只看"自 focus 以来被
改过"，**不看值是不是真的变了**。于是那一发按框里的旧值写回 `KP`，
紧接着 handler 才把它删掉 —— 顺序反着，按钮点了看着没反应。

★ **门闩（`krst`）拦不住它** —— 那一发在 handler 之外。我先试了门闩，
  白试一轮。正确的是**幂等守卫**：这一发的值与 `KP` 里已有的完全相同，
  那就什么都不做。
  ```js
  const _cur = (KP[id] || {})[k];
  if (v === a2.default ? _cur == null : _cur === v) return;
  ```
★ 诊断方法上的教训（又一次）：我连猜了五轮（并发？TDZ？blur？门闩？），
  每次都改完再跑。**该在第一次就把时序打出来** —— 两行
  `console.log(performance.now())` 就定位了（同「持仓表排序」那次）。

★ 判据三条，各对应一种不报错的坏法：换指标**零请求**（+反向自证换复权/
  区间仍会重取，否则"永远不取"也全绿）、加载中**不许清掉画布**
  （拦住一个接口不放行，在"还没回来"的那一刻量）、改完参数**焦点还在框里**。
  5 条变异 4 条抓到；「缓存键不含 FQ」是**无效变异** —— 换复权走 `load()`，
  它每次都重取并覆盖缓存，当前流程下没有可观察的错误。

★ 「展开」**只在真的被截断时**才露出来（渲染后量 `scrollHeight`），

- **同一行几张卡的画布 `top` 必须完全相同** + 反向自证"真的有一行多张"
- 「截断」与「展开按钮可见」必须**一一对应**，再反向自证"真有一张被截断"
  （否则是"全 False == 全 False"）
- 截断要**按整行切**（可见高度是行高的整数倍）
🔴 判据**不能用 `display` 是不是 `-webkit-box`**：Chrome 对这个 legacy 值的
  computed style 报 `flow-root`，拿它当判据在正常代码上就先挂了。
★ `.ihead` 改成 flex 是**无效变异**（当前 min-height 下 flex 压缩恰好也切在
  同一位置，可见行为相同）；真正抓得住的是「必须有一条被截断」那条
  —— clamp 行数放宽到 6 行、min-height 放到 260px 都被它抓到。

★ 分页之后，既有那条「副图页签必须列全部副图指标」**过期**了（PER=9 < 10）。

  一起搬进翻页循环 —— 留在外面的话它会去找不在当前页上的卡，
  表现是 30 秒超时、看着像页面坏了。

## 🔴🔴 "卖 1 只、买 0 只"——两个缺陷叠在一起（2026-09-14）

用户问「为什么是卖出一只、买入 0 只？卖出原因是调仓换出？」。
逐层查下来是**两个互相独立**的缺陷，任一个单独存在都会让买入腿消失。

### ① `RecordingBroker` 的卖出不落地 -> 买入名额算成 0

它「只记委托不撮合」，于是卖出**不改 portfolio**。而 froec 的买入腿是按
**只数**截断的：

    need = [c for c in target if c not in positions]
    need = need[:max(0, len(target) - len(positions))]

卖出没落地 -> `positions` 还是 10 -> `10-10=0` -> `need[:0]` **空**。
于是待办说"卖 1 买 0"，而同一份策略在回测里会买进替补 ——
**人照这份清单下单，卖完那笔钱就晾在账上了**。

★ 原 docstring **预见到的是"金额偏小"**（并说股数由实盘模块按真实现金重算），
  没预见到"那笔委托根本不产生"。副作用被低估了一档。
★ 修法：`target_value == 0` 时把持仓去掉、把估算的钱加回现金 ——
  「如果现在执行会发生什么」本来就包括这两件事。
  **只落地清仓**：买入需要成交价，而信号是给**下一个交易日**的，
  那天的价还不存在（这正是 RecordingBroker 存在的理由）。

🔴 这改动撞红了「唯一卖出出口」那条老守卫（全文件数 `positions.pop` == 1）。
  **没有把 1 改成 2** —— 那正是守卫烂掉的方式。改成按**类**判：
  记账那条路仍然只许一处且必须在 `_fill_sell` 里；预览那条路允许一处，
  但必须**证明无副作用**（不碰 trades / fills / fee_paid / div_tax_paid /
  buy_amount / sell_amount）。比原来的计数**更严**。

### ② `lu_since_start` 在实盘里表达不了"实盘开始之后"

froec 有这个开关（"起点前的涨停不算"），判据是 `g.start_date` ——
而它是 `prepare` 第一次跑时的 `current_date`：回测里那是回测起点（对），
**实盘里那是【重放窗口】的第一天**（30 个交易日前），不是开户日。

实测：重放窗口 **08-04** 起、账户 **09-01** 开户，而那两只的涨停在
**08-19 / 08-24** —— 打开开关也**仍在窗口内**，等于没开，**而它不报错**。

★ 修法：实盘模块把 `g.start_date` 设成**开户日** —— 喂真实初始状态本来就是
  它的职责（持仓、现金都是这么来的）。定义与「策略曲线」同一个
  （`lv/bench.py` 的 `created`），两处各写一份迟早分叉。
★ 只在策略**确实有这个概念**时才设（`hasattr`）。
★ 判据钉在 `had_limit_up(codes, lo, d)` 的 **`lo`** 上 —— 那才是这个修复
  真正要改的东西。**不钩 `prepare`**：`run_daily(prepare, ...)` 注册的是
  那一刻的函数对象，事后换模块属性对已注册的引用毫无影响
  （bench 那次踩过，这次又踩了一遍）。

### 两个都修好之后，剩下的是【配置】不是 bug

    现状（lu_since_start=0）  卖 1 买 0
    lu_since_start=1          卖 1 买 1（300980 祥源新材 2600 股）

买 0 的直接原因是：黑名单剔掉了前 10 名里的 2 只（301152 第 3、603506 第 6，
都"窗口内涨停过"），而 froec **默认不补位**（`fill_blacklist=0`，已实测为
−0.81pp，见上文）；同时 `lu_buy_only=1` 又让这 2 只**继续持有**。
于是 `持仓(9) > 目标池(8)`，买入名额 `8-9` 钳成 0。

🔴 **这是三个开关的交互结果，不是谁写错了**：`lu_buy_only` 让黑名单不卖票、
不补位让目标池缩水，两者一起就会出现"持仓比目标池还多 -> 不再买入"，
账户会在黑名单的 20 个交易日里一直少一只、现金闲着。
★ 那两只的涨停（08-19 / 08-24）**都在开户日 09-01 之前** —— 账户那时
  根本没持有过它们。所以 `lu_since_start=1` 在这个账户上是**讲得通**的：
  它要问的是"我持有期间它涨停过吗"，而不是"它在我买它之前涨停过吗"。
  是否打开是**实盘决策**，不在这里替用户改。


## 业绩页分页签：业绩置顶，六块各一页（2026-09-15）

用户："都放在同一个页面太拥挤了，应该也和回测的结果一样的做成页签"
"业绩一直置顶，然后业绩曲线、收益明细、执行差异、每日持仓、交易记录、
清仓记录各自一个页签"。

```
KPI 板（累计收益 / 加权年化 / 最大回撤 / 当前回撤）—— **一直置顶**
业绩曲线 │ 收益明细 │ 执行差异 │ 每日持仓 │ 交易记录 │ 清仓记录
```

★ 页签用的是**回测详情页那一套**（`#tabs` 的样式加一个选择器
  `#tabs,#lptabs`，不复制）—— 抄一份的话两页的页签会慢慢长得不一样。
★ **切页签才渲染**（懒渲染）：持仓/交易记录/清仓记录各要打一次接口，
  进页面就全打的话第一眼要看的曲线被拖慢，而那三块多半没人翻到。
🔴 **容器按 `LP_TABS` 的 id 找，不按下标写死** —— 下标写死的话调一次顺序
  就要改六行，漏一行的表现是"点某个页签是空的"。
🔴 **执行差异我原本排最后**（理由是"复盘才看"），用户把它放第三 ——
  那是他的使用顺序，照做。**这种事不替用户判断。**

### 🔴 交易记录 ≠ 清仓记录，是两个不同的东西

| | 视角 | 回答 |
|---|---|---|
| **交易记录** | 逐笔操作：买入、卖出**各算一笔** | 那天我做了什么 |
| **清仓记录** | FIFO 往返：一买一卖配成一笔 | 这一笔赚了多少 |

用户原话："买入卖出都算一笔单独的操作，需要记录下来，这才是真正的交易记录。
已清仓的单独放一个。"

★ 逐笔那张表与**流水独立页共用 `fillsTableHtml`**（从 `showFills` 里抽出来）
  —— 同一份数据两处渲染，列序/冲正标记/估算标记会慢慢分叉。
★ 业绩页那份**不给冲正按钮**（冲正是"更正录入"，属于流水页那条链），
  但给一条链过去 —— 不给可以，**不能藏起来**。
★ 判据不能只查"有这两个页签"：要查**行数关系**（逐笔 >= 往返 × 2，
  一笔往返至少对应一买一卖）+ **表头不许串**（交易记录里出现"持有天/收益率"
  就是接错了数据源）。变异实测：把两边接口对调，只查"页签存在"照样全绿。

★ 判据是**逐格对服务端**，不是"表头有那一列" —— 后者在前端推错方向时

    改之前  KPI 板 `a.lpin`「累计收益 ›」          ← 唯一入口，名不副实
    改之后  账户按钮排「📊 业绩」（记一笔 · 业绩 · 流水 · 选股理由）
            KPI 那一格退回**纯数字 + 口径 ⓘ**

★ 这与「看不出能点的入口 = 没有入口」是同一条纪律的另一半：
  **看得出能点** + **名字说得出去哪**，缺一个都不算入口。

★ 「怎么进业绩页」收进 `_base._lp_enter` 一处（同 `_kmain` / `_via_pop` /

#### ③ 交易统计：**在服务端算**（`lv/hist.trade_stats`）

回测的 `stats.json` 早就有 `n_trades` / `win_rate` / `profit_factor` /
`avg_win` / `avg_loss` / `avg_holding_days`，实盘这边一个都没有。
现在 KPI 板第二排四格（平仓笔数 / 胜率 / 盈亏比 / 平均持有），
清仓记录页上方两张榜（盈利榜 / 亏损榜）。

🔴 **不能让页面照 `/api/live/trips` 算** —— 那个接口是**分页**的（默认 100
  条），照页面手上那一页算胜率会**随翻页变，而它不报错**。判据是
  `n == 全量行数`，而这条**必须构造 >100 笔往返才测得到**（真账本只有
  2 笔，写死一个小账户等于空转）。
🔴 **两张榜只列真的**：往返少时「盈利前十」里会混进反号的那些 ——
  实测 froec 只有 2 笔往返时就列出一笔 **−0.21%**，名不副实。
  列不满十条是**事实**，标题里写真实条数（写死"前十"就是在说谎）。
🔴 **一笔亏损都没有时盈亏比给 `None`，页面显示「—」** —— 给 ∞ 或一个很大的
  数会看着像"这个策略很厉害"（同「拿不到分红那一格标查不到，不猜一个数」）。
★ 盈亏比用**收益率**口径的 `平均盈利 / |平均亏损|`（与回测的
  `profit_factor` 同义）：用金额算的话一笔大仓位会把它带偏，
  而这一页问的是"选得准不准"，不是"下注多大"。
★ 极值那条判据走**另一条独立的路**取（`round_trips(limit=10**9)` 自己排序），
  不拿 `trade_stats` 的输出当期望 —— 判据要独立（同「判据拿被测对象当期望」）。
★ 一次取、两处用（`LPTS` 按 aid 缓存）：KPI 板与两张榜各打一次接口的话，
  同一份数据要重放两遍往返配对。**缓存必须带 aid**，否则切到另一个账户
  还显示上一个的胜率（同「基准要按账户记」）。

★ 8 条变异全抓到（服务端 3：照当前页算 / 榜不过滤 / 没亏损给大数；
  前端 5：方向自己推 / 胜率自己算 / 榜不过滤 / 入口画成灰字标签 /
  入口名字改回「累计收益」）。
⚠ 如实记：服务端那条「榜不过滤」是被**「全赚的账户不该有亏损榜」**那句
  抓到的，不是 `all(ret > 0)` 那句 —— 130 笔的构造里前十本来就全是正的。
  两句都在同一条用例里，但**别把功劳记在错的那句上**。

#### 🔴 顺带修一条【构造依赖今天星期几】的用例

全量跑的时候「模拟盘盘中推进」红了，而产品一个字没改 —— 它借用真账户 a2
（`froec_traded`），于是那一半悄悄依赖两件"真实数据碰巧如此"的事，
这天两件一起翻车：

    ① NEXT 要恰好是那个策略的调仓日。froec_traded 只在**周内第 2 个交易日**
       调仓，而当天 16:xx 的同步把面板推到 09-22（周二）之后
       NEXT = 09-23（周三）-> 策略一个委托都不下 -> 「一笔都没写」
    ② 就算撞上调仓日，a2 当时**满仓、只剩 193 元现金** ->
       买入腿"资金不足一手"、卖出腿"收盘跌停无对手盘" -> 照样 0 笔

★ 修法是**把账户也构造出来**：空仓 + 满现金的模拟盘，并把调仓日**设成
  NEXT**（算出 NEXT 在它那个 ISO 周里是第几个交易日，喂给 `weekday`）——
  于是它在那天必然建仓，与今天星期几、真账户什么状态全无关（实测 10 笔）。
🔴 `weekday` **只能设成 NEXT 自己的序号**：引擎的周序号表按 **feed 里有的
  交易日**算，而 feed = 面板(≤panel_last) + NEXT —— 只有"紧挨着的下一个
  交易日"序号才是对的。实测隔一天的 09-29 算出来是 `(1, -1)` 而不是
  `(2, -1)`，于是"往后找一个调仓日"这条路**根本走不通**（我先试的就是它）。
★ 这条用例的注释里本来就写着「同『判据不许依赖真实数据碰巧如此』」——
  **它防住了别人，没防住自己**（借用真账户这件事本身就是那个依赖）。

| | |
|---|---|
| **旧 hash 保留并 redirect** | `#/live/<id>/fills` 与 `#/live/<id>/why?d=…` 是书签、也是持仓行那个 `?` 的地址 —— **产品契约**（同「.html 一律留在根目录」）。`app.js` 里跳到 `#/live/<id>/perf?tab=…`，**参数一起带过去** |

## 实盘不许比回测少：每日持仓 + 交易记录（`lv/hist.py`，2026-09-15）

用户："发现实盘功能反而没有交易记录、每日持仓，实盘的信息不应该比回测少。"
对照下来实盘缺两块，都补在**业绩页**（`#/live/<id>/perf`，那本来就是复盘页）：

| | 回测 | 实盘（补之前） |
|---|---|---|
| 每日持仓 | `holdings.parquet` 逐日快照 | 只有**当前**持仓 |
| 交易记录 | `trades.parquet` 一笔平仓的收益率/盈亏 | 只有成交流水（**录入视角**） |

🔴 **数据本来就有，只是没人把它展开** —— `equity_curve` 已经在逐日
`lots_asof(rows, d)` 重放持仓了，只是把逐只明细扔掉只留合计；成交也一直在
账本里，缺的是"按 FIFO 配对成一笔往返"这一层。**一个新数据源都没引。**

★ **表格复用回测详情页的 `tbl()`**（同一个 index.html 里的顶层函数）——
  两页各写一套渲染的话，排序、分组、数字格式会慢慢分叉。

### 🔴 最关键的自证：每日持仓的权益必须逐日等于【业绩页那条曲线】

两处各算各的话，"同一天两个总资产"不报错，只是两页对不上 ——
而这一页存在的理由就是复盘时对着看。所以 `hist._feed` 与 `perf.equity_curve`
用**同一套**日期轴与取价，断言里逐日比（还要反向自证日期真有交集，
否则 0 天对上也叫"全部一致"）。

### 🔴 三条口径，页面上都写出来了

- **权重的分母是当日总权益**（持仓 + 现金），不是持仓市值 ——
  后者会让满仓与半仓都显示 100%，而仓位正是要看的东西。
- **收益率含费**：买入费摊进成本、卖出费从收入里扣。而**回测那边的 `ret`
  只含滑点不含佣金**（为了与引擎 `entry_price` 同口径）——
  两边**本来就不一样，不该硬凑成一致**，各自标清楚更有用。
- **停牌按最后已知价挂账并标 `stale`**（同 `equity_curve`）：直接跳过的话
  那天市值凭空少一块；不标的话人会以为"这只票今天没动"，而事实是没有数据。

★ 未平仓批次也给（`n_open`/`open`）—— 回测的 `trades.parquet` 恰恰没有它们，
  而实盘"我现在拿着什么、成本多少"是天天要看的。

### ★ 断言里踩到的四处，每处都是同一类错：判据比要证的事宽/窄

| 踩到的 | 问题 |
|---|---|
| 挑账户只要"有成交" | 挑到 0 笔往返的账户，"收益率含费"那几条**整段静默跳过**。改成优先挑**有往返**的 |
| `abs(ret - naive) > 1e-9` | 变异成"不含费"后两者仍差 1e-10（`round(…,6)` 残差），**照样通过**。判据改成按**费用占成本**的量级给下界 |
| 停牌那段 | 当前账户没有停牌票 -> **整段空转**。改成**构造**（把某天的价从价格表里抹掉）才测得到 |
| 分页条 `NaN/NaN 页` | 字段是 `limit` 我写成 `lim` —— **接口断言看不到**（`total` 是对的），只有看页面才发现。补了"页面上不许出现 NaN" |

## 模拟盘（`lv/paper.py`）：让引擎替你下单，成交写进同一本账

**模拟盘 = 一个 `mode='paper'` 的实盘账户，它的成交由【引擎】产生。**
不是另做一套账，也不是"回测结果另存一份" —— 于是

    持仓 / 成本价 / TWR / 业绩页 / 收益明细 / 成交流水 / 选股理由
        ——— 一行新代码都没写，全部原样复用

🔴 **成交必须来自引擎。** 整手取整、T+1、涨跌停无对手盘、成交量上限、
最低佣金、印花税分段、红利税档位、停牌挂账、退市清算全在 `broker.py` 里，
在模拟盘里照抄一遍就是第二份实现（同「核心原则：不重写任何交易规则」）。
为此给 `Broker` 加了 `fills`（逐笔成交）与 `dividends`（分红到账）——
**纯投影**，等价性回归对过：froec / 红利指数增强 / ETF-P1 三个策略
2024 全年**完整报告逐行相同**。
★ `trades` 是**往返**记录（FIFO 批次、卖出时才写），拿它当流水会
  **丢掉所有买入** —— 变异测试第一条抓的就是这个。

🔴 **与业绩页那条「策略曲线」是【同一次构建】**（`bench.build_engine`）。
各建一份的话费率/滑点/gated 起点任何一处不同，就会出现"模拟盘的成交与
策略曲线对不上"，而那看着像哪一边算错了。

**推进 = 从开户日重放到最新数据日**，不是"增量跑几天"：策略的路径状态
（涨停黑名单 / 止损冷静期 / 吊灯窗口）是逐日累积的，只跑新的那段这些全是空
（同「warmup 必须逐日重放」）。代价是每次重跑一遍（1~3 秒），**幂等**。

### 🔴 账本仍然 append-only：对账不一致要【报出来】，不改写

数据会被修正（本项目修过 volume 74,952 行 / 复权因子 / ETF 价格刻度），
修正之后重跑，过去那几天的成交可能就变了。这时返回 `mismatch` 并**一个字节
都不动账本**（同「复算结果不许写回信号文件」）。要按新数据重来得显式
「重建」，而那是**删档重开**、只删 `source == 'paper'` 的行——
手工补录的那几笔不碰，实盘账户调它直接拒。

★ `mode` **建好之后不能改**：同一本账里混着真实成交与引擎成交，
  之后再也说不清哪一段是真的。

### 🔴🔴 顺带逼出一个实盘也有的 bug：TWR 把【分红】当成了外部入金

分红到账走 `cashflows.jsonl`（账本设计如此），而 TWR 的做法是"在每个有
外部现金流的日子把区间切开"——于是：

    除权日：股价掉下去 -> 权益跌 -> 记一笔**负收益**
    到账日：现金加回来 -> 被当成"入金" -> **不计入收益**

一来一回，分红那部分收益被**扣掉两次**。实测模拟盘红利账户：
期末/起点−1 = 5.83%，而 TWR 只有 4.39% —— 差 1.44pp，恰好是分红
7,876/500,000 = 1.575% 那个量级。
★ 这**实盘也有**，只是两个真实账户还没收到过分红，所以一直没暴露；
  是模拟盘按引擎跑出分红之后才把它逼出来的。

**已修**（`lv/perf.py`，2026-09-14）：`FLOW_KINDS = ('deposit','withdraw','adjust')`
—— 分红照常进现金（`cash()` 不动，它是真金白银），只是**不算外部资金**。

修完横扫了同类（同「改一处之前先扫同类」）：

| 用到现金流的地方 | 结论 |
|---|---|
| `perf.equity_curve` 的 `flow_by_day` | ← 就是这里，已修 |
| `stats.net_deposit` / `pnl_total` | 跟着 flow_by_day 走，自动正确（分红现在算利润） |
| `pos.cash()` / `cash_asof()` | **照旧含分红** —— 那是真钱，不能改 |
| `sig._replay` 把现金流喂进引擎 | **不会重复计**：它每天用账本现金**覆盖** `eng.pf.cash`，引擎自己派的息当场被盖掉 |
| `bench` 策略曲线 | 不碰账本现金流，无影响 |
| 页面 `net_deposit` 三处显示 | 跟着服务端走 |

★ `adjust`（手工调整）**仍算外部** —— 它的语义就是"这笔钱不是交易来的"。
  这是个判断，不是推导出来的；记在这里免得下次有人以为是漏了。
★ 对两个真实账户**一个数字都没变**（它们 0 条现金流，实测 TWR 与
  期末/起点−1 仍严格相等）—— 所以这次修复没有污染任何历史。
🔴 断言要钉**用户可见的后果**：只钉 `net_deposit` 的话，"TWR 把分红收益
  扣掉了"这件事本身没被覆盖。判据是「只有分红时 TWR == 期末/起点−1」，
  再配一笔真入金防矫枉过正（把 `FLOW_KINDS` 清空也要被抓到）。两向变异都验过。

### 🔴 账本与引擎天然差一点，差额必须【给数字】而不是假装相等

    ① 舍入 —— 账本存券商口径（价 4 位、费 2 位），froec 30 笔累计差 ~94 元
    ② **复权因子里含着分红、而分红表里没有那一条**：引擎是后复权总收益口径，
       这种分红表现成**价格上涨**；而账本记真实股数 + 不复权价，
       那笔钱既没进现金、价格又掉了 —— 账本【少掉一笔分红】。
       实测红利账户 601318 一只就差 486 元（因子跳 1.77%，不在分红事件里）。

★ 哪边"对"取决于问什么：对着券商对账单看，账本对；和回测比，引擎对。
  **所以不调和，只报差额**（`recon`：总差 + 逐只明细），页面上超过万分之五
  就标出来（同「对不上要说出来，不猜一个看着合理的」）。

### 🔴 模拟盘的入口：侧栏分【两个账户区】，不是顶栏第 8 个按钮（2026-09-17）

| `node --check` 扫全部 .js | **根本修复** —— 抓所有语法错。而 selftest 里**一直没有它** |

  检查等于没有检查。两条变异分别验过（真坏的抓到、安全的不报）。

#### 🔴 又一次：`goto` 换 hash 不重载，断言跑在【旧页面】上

「说明为空时主视图不留那一行」这条第一次是**红的**，而产品是对的 ——
`pg.goto('#/live/<另一个账户>')` 之后 `wait_for_selector('.lvhead')`
**立刻就满足**（上一个账户的还在），于是断言在旧页面上跑。
实测：切过去 **1.5 秒后**标题才换成新账户。
★ 判据要等**标题真的变成这个账户**（`wait_for_function` 比标题），
  不是等一个两个页面都有的选择器 —— 同「看着在验持久化、其实在读内存」
  那条的变体。

#### 🔴🔴 顺带逼出一个老 bug：切账户时【两发并发，旧的后回来】

「账户说明」那条用例**偶发红**（1/5），第一次报"没回填说明"、改严等待之后
变成超时。查下来是 `showLive` / `loadLive` **两处都有同一个竞态**：
它们 `await` 取数再写 DOM，而那几百毫秒里人可能已经切到别的账户。

| 表现 | 为什么不报错 |
|---|---|
| `loadLive`：往**脱离文档**的旧 `#lvbody` 写，紧接着 `$('#lvset').onclick` 是 **null** | 抛 `Cannot set properties of null`，**只在控制台里**（新页面自己会渲染，屏幕上看着正常） |
| `showLive`：旧那发把 `#main` 整块盖回去、`LVSEL` 也被覆盖 | 「hash 指向账户 A、页面显示账户 B」—— 真实场景就是**在列表里连点两个账户** |

修法是**代际计数**（`LVGEN`）：进函数时 `++LVGEN` 取号，await 回来若号变了
就作废自己。
★ 判据用**代际**不是 `location.hash`：`showLive` 也被非路由调用（建完账户、
  切「显示已归档」、收起侧栏），那几处 hash 根本没变。
★ `loadLive` 另加一道**容器判据**（`$('#lvbody') !== b`）：切走时容器被换掉，
  这道更直接；而代际挡的是"同一个容器上两发并发、旧的后回来拿旧数据盖新数据"
  —— 容器判据挡不住那个。

##### 🔴 两道守卫的分工，如实记（别把冗余说成"抓到了"）

    loadLive 那道   **根本修复** —— 变异当场抓到，堆栈精确指到
                    `live.js:397` 的 `$('#lvset').onclick`
    showLive 那道   **冗余防御** —— 构造出真并发之后变异**没抓到**
                    （旧那发回来时页面并没有被盖回去）。保留是因为逻辑上
                    它才是"页面显示哪个账户"的守门人，而 loadLive 只管
                    `#lvbody` 那一块

同 realtime 里「锁是根本修复、唯一 tmp 名防跨进程」那条 —— **别把分工记反**，
也**不要把没抓到的说成抓到了**（同「对数表里不许留只有数、没有判断的行」）。

##### 🔴🔴 构造并发**不能用 `pg.route` + `time.sleep`**

sync API 的 route handler 跑在 **driver 线程**上，`time.sleep` 会把后续请求
一起堵住 —— 两发被**串行化**，竞态根本没发生。
第一版这么写，于是「去掉 showLive 守卫」那条变异**没抓到**，
看着像"守卫没用"，差点据此把它删掉。

★ 正确做法：在**浏览器里**把第一发的 promise 延后 resolve
  （monkey-patch `window.j`，`await` 之后 `setTimeout` 再 return）——
  真并发，且不碰 driver。
★ 判据也不要固定等待：先 `wait_for_function` 等**新页面真的渲染出来**，
  再多等 2 秒让被作废那一发回来。固定等待在机器忙时读到半截。

##### 🔴 选择器要限定 `#main` —— 设置浮层里也有 `.lvhead h2`

浮层（`#stwrap`）的标题是"账户设置"，不限定的话 `wait_for_function` 等到的是
**浮层的标题**，而那与"页面切到哪个账户"毫无关系（判据比要证的事宽）。
实测报的是 `hash 指着 '红利混合-M'，页面却显示 '账户设置'` —— 一眼看出选错了。

### 🔴 刷新只换数字，不许重建 DOM（2026-09-09）

用户："刷新的时候感觉整个页面跳动了一下。是不是应该只刷新数字。"——是。
`loadLive` 一进来就把 `#lvbody` 清成「读取中…」，几百毫秒后内容才回来：
**高度先塌陷再撑开**，那就是"跳一下"。而这一页正是盯盘时一直开着的那页。

现在 quiet 轮询走 `livePatch(o)`：只换会变的那几处，DOM 结构一行不动 ——
滚动位置、hover、选中的文字全保住。改不动就返回 false，调用方再整块重建。

| 换什么 | 怎么换 |
|---|---|
| 持仓表 7 个实时列（现价/当日/当日盈亏/市值/浮盈/幅度/仓位） | 按 `data-rt="<code>\|<field>"` 找到那个 `td`，换它的 `outerHTML` |
| KPI 板（总资产/持仓市值/可用现金/持仓浮盈/当日盈亏） | 整块换 `kpiHtml(o)`（它没有交互） |
| 报价时间 | 换 `#lvday` 的 innerHTML |

🔴 **格子内容一处定义（`lvRtd`）**：渲染与刷新各写一份的话，"刷新之后的
数字格式跟首次渲染不一样"不报错，只是慢慢分叉。selftest 钉死：渲染路径里
不许出现手写的 `data-rt`。
🔴 **结构签名必须含【持仓代码序列】**，不只是只数（`lvSig`）：换了一只票
但只数不变时，逐格 patch 会按 code 找格子、找不到就**悄悄不更新** ——
新票那一行显示的还是旧票的数字，而它不报错。
🔴 **`#kperf2`（业绩板）要原样搬过去。** 它由 `liveEquityTag` 异步补进来
（轮询刻意不重拉它 —— 要重放整条权益曲线），而 `kpiHtml` 给的只是占位
「累计收益 …」。整块换会把它**抹回加载态**，`#lvkpi` 高度 177 → 161，
于是"数字都对、DOM 没重建，但页面还是跳了 16px"。
★ 头一版我保的是 `#kperf` —— 那是个**空的遗留容器**（`display:none`），
  保它等于什么都没保，而"高度还是变了"看不出是**保错了对象**。
  定位靠的是逐块量高度（`#lvbody` 的每个 child），一层一层缩小到 `#lvkpi`
  再到格子级 —— 只看总高度是查不出来的。
★ **轮询失败不要把已渲好的内容换成错误信息**：网络抖一下就把持仓表清掉、
  下一轮又回来，比不刷新更糟。安静跳过这一轮。

★ 这条用例的四组断言**各需要不同的构造条件**，混在一起测全是空转
（变异逐个抓出来）：

| 断言 | 要怎么构造 |
|---|---|
| DOM 没被重建 | 往某一行打 `data-mark`，刷完必须还在。只比高度的话，**重建出一模一样的 DOM 也算"没跳"**，而 hover 与选中的文字已经断了 |
| 数字真的换了 | 盘后价格不动，"更新了"和"没更新"**看不出来** —— 要在浏览器里改 `LVO` 的价格再调 `livePatch` |
| 漏字段（比如只换现价不换浮盈） | 同上，且要**逐字段**验，不能只验现价 |
| 换票要回退重建 | 构造"换一只票但只数不变"，断言 `livePatch` 返回 **false** |

### 🔴 回撤是【副图】不是第三个页签；一个页面只许有一个「‹ 返回」（2026-09-14）

用户："回撤曲线不应该是一个单独的页签，应该是跟随收益曲线和资金曲线，在下方
对齐。" —— 对。**回撤不是与另两条并列的"第三种看法"，它是对当前这条曲线的
注解**（"这一段跌下去有多深"）。做成页签的代价是：要看那个坑有多深必须切走，
而切走之后上面那条曲线就不在眼前了，只能靠记。

现在主图切换（收益 / 资金），回撤永远在下方共用 x 轴、高度减半（150 vs 300）。
★ **不需要任何对位代码**：两张图都走 `lineChart`，而它的 `W/L/R` 是固定的
  （1160/54/16）、SVG 又是 `width:100%` 等比缩放 —— **同宽即同刻度**。
  判据要**量出左右边界 + 比 viewBox 宽**，不能只查"两个 svg 都在"
  （把副图塞进 60% 宽的容器时，后者照样绿 —— 变异测试实测）。

🔴 **副图的口径必须【跟随主图】。** 资金曲线含入金、收益曲线（TWR 净值）不含：
入金那天总资产跳一截、峰值跟着抬高，于是"按总资产算的回撤"把后面每天都量深
一点，而净值那条根本没这回事。两张图摆同一屏而口径不同 = 自相矛盾。

★ **这条断言在真实数据上是空转的**：两个账户 `net_deposit=0`，两种口径
  **逐日完全相同**（实测最大差 0.000000）。必须**构造带入金的数据**才测得到。
  🔴 而且入金要落在**下跌途中**，不能落在峰值那天 —— 回撤是**尺度无关**的，
    在峰值入金之后两条同比例下跌，算出来一模一样。第一版我就是这么构造的，
    是断言自己把它抓出来的（落在下跌途中时 equity 创新高、回撤被重置，
    nav 继续加深，逐日最大差 0.0583）。

#### 🔴 回撤为 0 的点【照画】，不许断开 —— 断开只能意味着"没有数据"

用户："0 回撤到有回撤、有回撤到 0 回撤之间没有相连，看着有点怪。"

原来 `ddGap` 把所有 `dd == 0` 抹成 null，理由写在注释里：「那是"在水面上"，
不是"水下 0.0%"」。代价是每一段回撤**两头都不接水面线** —— 入水那天凭空
开始、出水那天凭空停住。实测 froec 账户：09-08 是**创新高**那天（回撤回到 0），
图上却是一个**空档**，于是

    第一次回撤跌到 −0.71% 就凭空停住（没画回到 0）
    第二次回撤从 −0.77% 凭空开始（没画从 0 跌下去）
    "09-08 回到历史最高"这个最明确的事实，图上完全看不见

🔴 **而空档在图表惯例里读作"没有数据"，意思正好反了。**

★ 顺带发现 `chart.js` 里水面线的注释本来就写着「**曲线贴着它走的那几段
  就是创新高**」—— 也就是说作者的设计意图本来就是画的，`ddGap` 一直在和
  它自己的注释打架。两处矛盾时，以"哪个说法更站得住"为准，不是以代码为准。

现在规则**没有例外：断开 = 没有数据**。至于"在水面上"这层意思，配 `hiCap:0`
时 0 就是画布顶边，曲线压在顶边上本身就看得出来，不需要用空档去表达。
`ddGap` 整个删掉（两处调用点 + 两处注释一起清）—— 留一个恒等函数比删掉更糟。

★ **判据不能只判"连续"**：把 0 抹掉之后**每一段各自仍然是连续的**

  **曲线顶点的 y 必须落在水面线的 y 上**（误差 < 1px）—— 创新高那天回撤
  正好是 0，曲线必须**碰到**水面线。两条一起钉（`nM == 1` + 顶点贴线），
  3 条变异全抓到。
★ 既有那条 `assert d['nM'] > 1`（钉的正是"必须断开"）是**被改动作废**的
  断言，改成钉新规矩而不是删掉保护（同 `#d_hold .note` 那条）。

🔴 顺带踩到：**模板字符串里的注释不许出现反引号。** 我在 `chart.js` 那段
`<!-- -->` 注释里给 `ddGap` 加了一对反引号 —— 那段注释在
``el.innerHTML=`...` `` 里面，反引号当场把模板闭合掉，**整个文件
SyntaxError**。`node --check` 当场抓到（同「注释里别写连着的星号加斜杠」）。

#### 🔴 两个「‹ 返回」，下面那个点了没反应 —— 同一个 id 出现了两次

用户："业绩上方的返回按钮点击没有反应，而且实盘的右边也有一个返回按钮，
为什么需要两个？" —— 没有理由，那是 bug。

`live-perf.js` 往 body 里又吐了一份 `backLink()` 的 HTML，却**从没调
`wireBack()`** —— 于是页面上两个一模一样的按钮，顶栏那个能用、body 那个
**点了没反应**（同「给一个点了没反应的按钮比不给更糟」那条）。
🔴 更糟的是两个都叫 `id="goback"`，而 `wireBack()` 用 `$('#goback')`
**只取第一个** —— 就算补调一次也只会把顶栏那个重绑一遍，body 这个永远是死的。
**同一个 id 出现两次本身就是 bug**，不是"少绑了一次事件"。

修法是删掉 body 那个：顶栏的 `pageHead` -> `backLink` 是所有页面统一出的那个，
已经绑好了。判据：全页 `#goback` 只许有 1 个、必须 `inTop`、必须有 `onclick`、
且点了 hash 真的变。
★ **测它必须从站内另一页进来**（本用例先开个股页再点顶栏「实盘」）——
  直接 `goto` 的话 `document.referrer` 为空，`backLink()` 两个都不渲染，
  "只有一个"这条断言就成了空转。

### 🔴 浮窗到了视口边缘要【翻到另一侧】

`lineChart` 的 tooltip 原来固定放光标右下（`clientX+12`）—— 光标移到图的
**最右边**时浮窗整块跑到视口外面，读数看不见。而那正是最需要看读数的位置：
曲线的最新一天。

`_tipAt(tip, cx, cy)`(shared/chart.js) 三步:
① 右边放不下 → 翻到光标左侧;② 下边放不下 → 翻到上方;
③ 最后把坐标**钳进视口** —— 极窄屏下两侧都放不下时,宁可压着光标也要可见。

🔴 **必须先填内容再量尺寸**:`offsetWidth` 在设置 `textContent` 之前是**旧值**,
用它算翻转会翻错边(第一版就这么错的)。

★ 这四条的断言各有各的构造条件,**混在一起测就是空转**(变异测试逐个抓出来):

| 断言 | 要怎么构造才测得到 |
|---|---|
| 水平翻转 | 光标在图的 97% 处,判据是**浮窗右边界 ≤ 光标 x** |
| 垂直翻转 | **正常高度**的浮窗 + 光标顶在底部 |
| 水平钳制 | 内容撑得**比视口还宽** + 光标顶在右下角 |
| 垂直钳制 | 内容还要**比视口还高**(只撑宽的话垂直翻转后本来就在视口内) |

★ 用"内容比视口还高"去测**垂直翻转**是错的:翻转与不翻转最终都被钳到
`top=4`,看不出差别 —— 实测去掉垂直翻转照样全绿。
★ 判据不能只写"浮窗在视口内":正常宽度下翻转之后本来就在视口内,
那样的断言分不出"翻转生效"和"恰好没超"。

★ 画图与分桶放 `web/shared/chart.js`(`lineChart` / `perfBuckets` /

"两页对同一段权益给出不同的月收益"不报错。

## 选股理由：为什么选它 / 候选池（`lv/explain.py` + `views/live-why.js`）

信号里每只买入的票都带**为什么**，浮层里给出**整期候选池**（谁没轮到、
谁被剔了、每只的指标各是多少）。入口在待办标题行的「选股理由」，
买入/卖出/持有行名称后面那个 **?** 是同一份理由的一句话版。

🔴 **理由是【捕获】来的，不是照策略再算一遍。** 与 `RecordingBroker` 同构：
把 `ctx.data` 换成透传的 `RecordingFeed`、把 `broker.filter_tradable` 换成记账
包装，策略跑自己的代码路径，我们只在旁边记下

    ① 查了什么（SQL 的入参 = 策略当时用的阈值：`pbcut=floor(0.5*n)` …）
    ② 查回来什么（候选池 + 指标列，**带原始顺序 = 排名**）
    ③ 每一步过滤前后的集合差（谁被筛掉了）
    ④ 过滤的理由**问规则本身要**（`broker.can_trade` 返回的 why），不自己判

照策略再写一遍筛选条件是最省事的做法，然后两份逻辑开始分叉，
**而分叉的那份看着完全正常**，只是某天开始解释错了（同 f133 那个股息率、
同前端硬编码"权不权威"）。
★ 判据钉在 selftest 里：**挂上记账代理之后，买/卖/持有清单必须逐位相同**。
★ 状态只从三个**事实**推：买了 / 持有着 / 卖了。通过了所有能观察到的过滤却
没被买，只说「没轮到（第 k 名）」，不说"因为只取前 10 名" —— 那是策略的规则。
解释不到的地方**明说不知道**，不猜一个看着合理的。

**唯一需要动策略的地方：末层 SELECT 多返回几列**（指标）。那是**投影**改动
—— `WHERE` / `ORDER BY` / `LIMIT` 一个字不动，行与行序完全相同，
`df['jq_code'].tolist()` 拿到的还是同一个列表。
★ 不另写一条"取指标的 SQL"：它算出来的 PB 与策略当时用的 PB **看着一样**，
直到某天 as-of 规则差一天（停牌股结转、报告期切换）才分叉，
而那时没人会怀疑一个"显示用"的数字。
★ 没改的策略照样能解释，只是没有指标列（`notes` 里会说明）。
🔴 等价性是**实测**过的，不是推理：2016-01~2026-08 全历史，froec 与红利
逐日权益指纹 + 成交流水指纹（进出场日/代码/股数/价/原因）**逐位相同**。
selftest 里另钉一条更快的直接判据：同一天把宽投影与"只返回 jq_code"对跑，
代码列表必须逐位相同。

🔴 **改了策略文件，实盘不会自动跟着变** —— 账户绑的是**版本快照**
（`live/<id>/code/<sha>/`），`_load_snapshot` 读的是快照不是磁盘。
所以要让新指标出现在信号里，得在策略浮层里**重新绑定一次版本**；
在那之前页面会显示"磁盘文件与绑定版本不一致"。这是保护不是麻烦：
它保证了"改了磁盘上的策略"不可能悄悄改变实盘信号。

**指标的中文标签、量纲、名次配对在服务端**（`explain.METRICS` /
`RANK_PAIRS` / `metric_meta`），页面**不认识任何一个列名**。
🔴 `dy` / `inc_*` 这些比率在 std 层是**小数**（0.05 = 5%）——
标错量纲页面会显示 "0.05%"，而那看着像个正常的小数字。
★ 对不上的列**不丢，按原名显示**：策略新加一列时最坏是标签丑，
而不是那一列凭空消失（消失了没人会发现）。

### 形态：独立页 `#/live/<id>/why`，一期一段按排名列出

入口是账户页顶部的**按钮**「选股理由」（与「流水」并排），持仓表每行名称后的
**?** 直接跳到**它建仓那一期**（`?d=<日期>`）。

🔴 **一开始做成了浮层 + 待办标题行里一个 `.lvwhy` 小链接，实测人找不到它** ——
那个链接与旁边的「版本 9FB82061」样式一模一样，**一个能点的东西被画成了标签**。
这是 backLink 那条的反面：给一个点了没反应的按钮很糟，
而**看不出能点的入口 = 没有入口**，同样糟。改成按钮 + 独立页
（这一页每天长一期，会越来越长 —— 同成交流水那条：**服务端分页**）。

**默认只列调仓日**，可切「含非调仓日」。非调仓日不选股，列出来是几段
"本期不选股"的空段 —— 实测 froec 最近三期全是非调仓日，第一页什么都没有，
真正要看的那期被挤到第二页。

每一段：期头（日期 / 调仓日 / 数据日 / 版本 / 买卖持有几只 / 几组查询 /
是不是事后复算），然后 **一条查询 = 一块**：块头是组名 + 返回几只，
下面是「条件」（参数 chip + 可展开的**完整 SQL**）与**按排名升序**的表。
状态分五种：**选中·买入 / 选中·持有 / 卖出 / 没轮到 / 被剔除**，
再加策略自己的集合标签（**备选** / 缓冲区 / 目标池 —— 来自 `g` 里那几个
代码集合，`SET_LABEL` 在服务端翻译，页面不认识业务语义）。

🔴 **绝不能把多条查询并成一张表。** 第一版并了，还按代码去重 —— 对红利那种
「低波(A) + 价值(B) 两袖并集」的策略实测坏三处，而且都不报错：

| 症状 | 根因 |
|---|---|
| B 袖那一组**0 行** | 6 只全被去重并进 A 袖；再叠加"全局 60 行上限"，小的那组被 A 袖填满后一行不剩 |
| B 袖选中的票显示成**第 233/332 名** | 只留第一次出现的名次 —— 而它其实是被 B 袖第 1 名选中的，"第 233 名却买了它"看着莫名其妙 |
| **市值 / 净资产收益率整列空白** | 两袖指标不同（A 是 dy/beta，B 是 totalmv/inc_*），并表后各空一半 |

两条腿是**两套规则、两套指标、两套排名**，本来就该是两块。一只票同时出现在
两组里就两组各出现一次，各带那一组的名次与指标 —— 那是事实（并标「也在第 N 组」，
否则 A 表里那行"第 233 名 · 选中·买入"会被读成"A 选的"）。截断也**按组**做。

🔴 **froec 原版 `LIMIT 10`，所以它的候选池只有 10 行** —— 页面列不出
"差一点选上的是谁"（红利那条 SQL 返回几百行，本来就能列到 20）。
2026-09-07 加了 `g.explain_pool`（默认 20）：**查得比用得多几名**，
`WHERE` / `ORDER BY` / `OFFSET` 一个字没动，只放大 `LIMIT`，
而 `ORDER BY floatmv ASC` 是确定序 —— 全历史逐位等价（2593 行权益 +
949 笔成交指纹相同）。
🔴 **关键是那一刀 `cand = df['jq_code'].tolist()[:lim]`** ——
不截断就等于**开了补位**：过滤（tradable / 止损 / 黑名单）发生在截断**之前**，
名额会被后面的票补上。而补位是 `fill_paused` / `fill_blacklist` 那个
**已测为负**的开关，不能顺手打开。selftest 里两条一起钉：等价性 +
"候选池确实从 10 变成 20"（后者防的是等价断言变成空转）。

**存 60、显示 20。** 20 名之后全是"没轮到"，看不出信息；但**存少了就永久没了**，
所以落盘留余量、页面默认只到第 20 名，可展开。
🔴 「一定要显示/一定要落盘」的**不只是买卖持有**：策略自己点过名的
（备选 / 缓冲区 / 目标池）和**被规则剔掉的**也必须留 —— 前者是"差一点就选上"、
后者带着剔除原因，正是有信息量的那部分。只按名次切会把排在 40 名的备选切掉。
★ 名次跳号要**明说**（`… 第 21–174 名省略（都没轮到）`）——
直接跳过去看着像数据缺了一块。

🔴 **"策略的条件"以 SQL 为准，不另写一份。** 只列几个参数 chip 是不够的：
条件长在 WHERE / 排序 / 截断里（`dy > 0.03`、`rk <= floor(0.1 * n)`、
`ORDER BY beta ASC`），另写一份"条件说明"就是第二份口径，策略改了它不会跟着变。
页面给的是**代入参数之后**的 SQL（`{dmin}` 已经变成 `0.03`），就是当时真跑的那条。
★ 组名让**策略自己在 SQL 首行写注释**（`-- 袖A｜红利低波：…`）——
注释改不了任何行为，却让"这一组是哪一袖"看得见。没有注释就只显示「第 N 组」，
**不要退回"SQL 的前 60 个字符"**：那会把 `WITH div AS ( WITH raw AS (…` 印成组名，
比没有名字更糟。判据是建仓日（FIFO 第一批
的成交日）== 信号的 `for_date` —— 对不上任何一期的（手工买的）**不给标记**，
硬凑一个出处比没有更糟。

🔴 **老信号里没有理由**（这个功能 2026-09-05 才加，而当前持仓来自 09-01）。
那几期只能**事后复算**：从那一期的信号里取回 `data_asof` / `code_sha256` /
`params`，把面板截到当时、持仓与现金按当天收盘后的状态（`lots_asof` /
`cash_asof`）、版本与参数用当时那套，照当时的账重跑一遍。

★ **复算完必须对账，而且结果要长得不一样**：把复算出的买/卖/持有与信号里
存的逐个比 —— `same` 说明面板没被动过、这就是当时那份；`differs` 说明
**不是当时那份**（面板被修正过 —— 本项目修过 volume 74,952 行、复权因子），
页面上要照实说、只能当参考。selftest 里有变异测试：把存档的买入清单改掉一只，
对账必须报 `differs`，否则那个 `verified` 是空转的。
🔴 **复算结果不许写回信号文件** —— 信号是 append-only 的证据「当时说了什么」，
把今天算的塞进去就是篡改记录。它落在**旁边**：`signals/_explain/<date>.json`
（`explain_side_path`），带 `recomputed` / `verified` / `for_sha`。
证据与派生物分开存，"这份理由是当时留下的还是后来算的"才分得出来。

🔴 **旁挂必须放【子目录】，不能是 `<date>.explain.json` 那种同层同名。**
有三处在扫 `signals/` 下的 `*.json`（`sig.latest_signal` / `px.latest_signal` /
`explain_history`），同层的话它们会把派生物当信号读进去，而 `latest_signal`
取 `sorted(...)[-1]` —— **出不出错取决于日期字符串的运气**
（`.explain.json` 恰好排在 `.json` 前面，所以"碰巧是对的"）。
放进子目录之后 `os.listdir` 只看一层，结构上就撞不上。

🔴 **不能只缓存在进程内。** 原来是 `_RECOMP` 内存字典，于是重启一次 serve.py
就全没了，人打开页面看到的是「这一期没有留下选股理由」加一个按钮 ——
**看着就是功能坏了**（实测用户反馈：「我直接看不到上一期选股」）。
现在是**三层**：进程内 → 旁挂文件 → 真复算。
★ 而且**打开就自动开算**，不等人点：复算要重放 30 天 warmup（1~3 秒），
太慢不能在请求里同步跑，所以 `srv/live.py` 的 `_explain_kick` 起后台线程、
接口返 `explain_pending`，页面显示「⏳ 正在事后复算…」并**每 2.5 秒自己回来看**
（用 `location.hash` 当护栏，人走开就不再渲染）。
🔴 光有按钮不行，光有后台也不行：不说"正在算"那一段就是一句"没有理由"；
不轮询就永远停在"正在算" —— **两种都不报错**。selftest 两条都钉着，
且断言匹配**完整条件** `if(p.explain_pending){`（只查标识符的话
把它改成 `if(false){` 照样全绿 —— 同 `prune_runs` 的 `h.pruned` 那条）。

🔴 缓存与旁挂都**按绑定版本**认账（`for_sha`）—— 复算的"指标"那一半会用当前版本
（见 `metrics_from`），重绑之后结果就变了。不带版本的话页面还是旧那份，
**而它不报错**（实测：给 SQL 加了组名注释、重绑之后组名死活不出来，就是这个缓存）。
★ 旁挂**不入版本控制**（`.gitignore` 里 `live/*/signals/_explain/`）：它是派生物，
按当前绑定版本算，重绑一次整份重生成 —— 入库只会制造无意义的 diff；
删了也不丢东西，下次打开页面自动重算。

实测：froec 与红利的 2026-09-01 那期（当前持仓的来源）复算结果都是 `same`。

★ **候选池是浮层，不是主视图里的第三块**：主视图的信息架构是
「今日待办 + 当前持仓」两块（selftest 钉着 `len(secs) == 2`），
候选池是研究/复盘时才看的。理由也不在买入表里占一列 ——
那张表是照着下单用的，多一列长文字会把要看的数字挤出屏幕。

### 🔴 加这个功能时捕获到的五个既有 bug（外加一条过期的断言）

| | 表现（都不报错） |

## 🔴🔴 持仓估值取价：快照只在【比面板新】的时候才盖住面板（2026-09-29）

|---|---|---|
| `positions_valued`（持仓表） | 实时快照 | 11.15（14:59 那次轮询） |

成因：实时链「收盘不轮」，收盘后一直拿着最后一次轮询的价；当晚同步把面板
建到**同一天**之后，面板有的是正式收盘价，而 `positions_valued` 仍无条件
让快照覆盖它。

🔴 **判据是「哪一份更新」，不是「有没有实时价」**：

```
盘中    面板停在 D−1、快照是 D   -> D > D−1，快照赢（盈亏要是活的）
收盘后  面板已到 D、快照也是 D   -> 不更新，面板赢（正式收盘价）
比面板还旧的快照                -> 一样不许盖（陈旧快照更危险）
```

同「判据永远是【现在的状态】」：不问"实时链开着没"，问"这两份数据各自
截到哪一天"。

★ **构造两种局面都要测**：真实数据一天里只碰得到其中一种，靠它自然发生的话
  另一半永远在空转，而看着全绿。`t_px_source_rule` 打桩 `realtime.latest`
  的 `at` 日期，把三种（更新 / 同一天 / 更旧）都跑一遍，最后再钉一次
  「累计收益 == 持仓浮盈」——那才是用户看得到的那条。

★ 取**引擎自己算的那份**：`Engine._declared`（initialize 期间真被写过的

## 🔴🔴 现金透支：持仓市值 > 总资产，而那句话指不到任何原因（2026-09-29）

用户报：「FROEC-TRADE账户的持仓市值超过了总资产」。

持仓市值 **407,001** > 总资产 **406,213.95**，差额 **787.05** —— 正好等于
现金余额（**负的**）。

### 倒查：一笔买入超出了当时的现金

把 17 笔成交逐笔重放，现金在**最后一笔**变负：

| | 下单时手上那版信号（rev4，09-29 01:00 建） | 实际录入 |
|---|---|---|
| 卖 603506 | 3300 股 @12.21 | 3300 股 @12.23 ✓ |
| 买 300165 | **7800 股**，限价 5.18，占用 40,404，预计剩 101.53 | **8400 股** @4.92 = 41,333 |

卖出后可用 40,545.95：买 7800 股花 38,381（剩 +2,164.95）；按成交价 4.92
现金买得起的上限是 **8200 股**；实际录的 8400 股花 41,333，**剩 −787.05**。

两笔都是 `source: "manual"`（09:40:46 / 09:41:32 手工录入）。
排除过：无分红、无公司行动、无出入金。

### 账务上唯一说得通的解释：先入金再买入

券商**不会**让资金不足的委托成交。所以现金变负只有两种可能：
① 录入的股数/价格与对账单不符；② 实际是先入金再买入，而那笔入金没录。

用户定的是 ②：「这种情况下说明实际增加了现金，等同于做了一笔现金
+787.05，然后再买入。并且收益率等等也要按照这个最新的本金来计算」。

于是补一笔 `kind='deposit'` 的现金流水（`live/froec/cashflows.jsonl`）。

🔴 **不改 `init_cash`** —— 入金是个**事件**。改 `init_cash` 会把这 787.05
**追溯到开户日**，过去每一天的权益都跟着变，而回看历史时没有任何痕迹说明
它变过。`add_cashflow` 的 docstring 早就写着这条，这次是第一次真用上。

补完之后（逐项量过）：

| | 改前 | 改后 |
|---|---|---|
| 现金 | −787.05 | **0.00** |
| 持仓市值 / 总资产 | 407,001 > 406,214 🔴 | 408,846 = 408,846 ✓ |
| 本金基数 | 400,000 | **400,787.05**（`init_cash` + 净入金） |
| 累计收益金额 | 8,058.95 | **8,058.95**（一分没变） |
| TWR | 2.0147% | 2.0138% |

★ **最硬的那条自证**：累计收益金额**一分没变**。`twr` 里
`(e − f) / prev_e` 把当天的现金流 `f` 剔掉、
`pnl_total = 期末 − init_cash − 净入金`、费用比例的分母是
`init + net_deposit` —— 三处口径本来就都对，入金是**本金**不是利润。

### 系统这边：只拦负持仓，不看现金

`add_fill` 有「这笔卖出会让 X 在某日持仓变负」的拦截，**没有现金那一条**。
录一笔会透支的买入时一声不吭，页面上只剩「持仓市值 > 总资产」这个症状。

新增 `lv/pos.py:cash_alert(aid)`：

- **不拦**：信用账户本来就能透支，硬拒会逼人绕过整个入口
  （同「硬拒必须配一个显式的逃生口」）
- **不替人补**：补错了就是凭空改本金，而收益率全跟着变
  （同 `corp_conflict`：报出来，别替人决定）
- 说的是**差多少、哪天起** —— 只说"现在是负的"等于让人自己去翻流水
- 只在真透支时出现 —— **常驻一条"一切正常"等于教人忽略这个位置**

页面（`views/live.js`）在「可用现金」那格标「透支」+ 副标题写差额，
