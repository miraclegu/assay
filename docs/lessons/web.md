# 看板与前端 —— 踩坑详情

正本索引在 `assay/CLAUDE.md`。**改 web/ 下任何东西之前**读这一册；里面每一节都是实测定案（有现场、有判据、有变异结果）。

## 看板的信息架构（改导航之前先读）

**打开 `/` 是总览首页**,回答「今天什么状态、要做什么」——
六块:实盘待办与持仓 / 盘面速览 / **买点到价** / 自选异动 / 数据新鲜度 /
选中的规则前 5。
🔴 **回测归档搬到 `#/runs`** —— 它是做策略时才进的,不该是第一眼看到的东西。
★ 首页每块只给**摘要 + 一个入口**(标题本身就是链接),**不重复做那一页的事**
—— 做成小型全功能页的话,同一份数据两处渲染,迟早不一致。
★ 顶部横条只在**真的要做什么**时出现(有待办、行情落后)——
常驻一条"一切正常"的横幅等于教人忽略这个位置。

**顶栏按使用频率分四组**(`common.js` 的 `NAV`,第五个字段是组名):

```
assay 总览 │ 💰实盘 🎯买点 │ 🌡盘面 📈个股 ⭐自选 │ 📚回测 │ 🔄数据
             每天必看        收盘后看行情、研究某只票  做策略   出问题时
```

🔴 **板块与对比不在顶栏,它们是【子页】**(2026-09-14,9 个入口 -> 7 个):

| 子页 | 从哪进 | 为什么是它的子页 |
|---|---|---|
| 🏭 板块 `/sector.html` | **🌡 盘面** | 盘面就是"今天各板块怎么样",板块页是它的下钻 |
| ⚖ 对比 `/compare.html` | **📈 个股** | 对比一定是"拿【这只】和别的比",起点就是个股 |

★ 两个页面**都还在**,书签与深链接一个都没失效 —— 那是产品契约
  (同「.html 一律留在根目录」那条)。变的只是顶栏少两个按钮。
🔴 **子页的顶栏要点亮父级**(`pageHead('market', '🏭 行业板块')`)——
  NAV 里已经没有它们自己那一项,传旧 key 的话**一个都不亮**,
  进去之后"我在哪"没有任何指示。★ 亮的是所属组,**标题仍写它自己是什么**。

🔴🔴 **合并的风险不是少两个按钮,是把功能藏起来。**
用户问「板块的功能是否盘面已经包含了」—— **没有**:盘面只有
「行业涨幅(申万一级)」一张表,而板块页是 **5 类 926 个**
(申万 + 通达信 概念 269 / 风格 158 / 地区 32 / 研究 467)带成分股穿透。
合并前那 657 个通达信板块**只能从顶栏进**,顶栏一撤就再也没有入口了 ——
**而那不报错,只是从此没人找得到**(同「独立页面最大的风险是页面之间断链」)。
所以盘面的「行业涨幅」标题行右侧补了类别 chip(`按别的分法看：概念 269 ›…`),
个股的「⚖ 拉去对比」也改成**带着当前这只票**过去(原来链的是裸页面,
到了那边还要再搜一遍 —— 那是把入口做成了摆设)。

★ **判据取服务端的清单,不写死**:`/api/sector/kinds` 说有几类,盘面就得
  链得到几类。照清单写死的话,将来加一类不会有人发现
  (同「断言直接扫目录而不是照清单拼」那条)。6 条变异全抓到。
★ 顺带修一条写死的断言:个股页那条 `#top .btn.nav >= 8` —— 顶栏一合并
  就挂了,而**挂的是断言不是产品**。改成与 `NAV.length` 比,下次增减入口
  不用手改。

- **实盘 + 买点排最前**,两个都带告警红点(`navAlert` / `alertDot`,判据都是
  **服务端**给的:`live.signal_alert` / `alerts.valued` 的 `n_hit`+`n_near`)
  —— 它们是回答"今天要做什么"的两个入口(一个是策略的,一个是手工挂单的)
★ `setAlertDot(o)` 与 `alertDot()` 分开:买点页自己已经取过那份数据,
  再让红点去打一遍接口就是同一份取两遍。而且**改完一行要立刻更新红点** ——
  只在页面加载时点一次的话,刚加的那只到价了红点还是灭的,**而它不报错**。
- **分隔线是信息不是装饰**:告诉人"这几个是一类,可以一起扫"。
  平铺 8 个时每次都要在 8 个里扫一遍才找到要去的地方
- **「assay」这个站名就是首页入口**,不再单列"🏠 首页"(左上角点回首页是通用
  约定);在首页时点亮,否则"我在哪"没有指示
- **数据字典并进「🔄 数据」的页签** —— 同步(新不新)与字典(口径是什么)都是
  **数据的元信息**,而且都是低频。`#/docs/<key>` 仍是直达路由,旧链接不失效

★ index.html 承载多个 hash 视图,所以**标题与高亮跟着 hash 变**(`syncHead`)
—— 固定写死的话在实盘页也会显示"回测归档",而顶栏高亮本来就是用来告诉人
"我在哪"的。过滤框/全部展开只在 `#/runs` 出现(别处是噪声),
所以它们的**事件绑定也要在进入那个视图时做**,不能在页面加载时一次性绑。

🔴 各视图开头统一用 `enterView()` 收拾,**不要每处抄三行** ——
`#filter`/`#expand` 只在某个视图存在,别处 `$('#filter')` 是 `null`,
抄一遍漏一处就是 TypeError 整页白屏。

★ **目录也按【产品域】分,与 index.html 的拆分同一判据**(2026-09-04,
根目录 21 个文件平铺 → 8 个 + 2 个目录)。`shared/` 与 `views/` 的分界是
**"谁在用"**:6 个独立 .html 也要 `common.css`/`common.js`/`kchart.js`,
而 `live.js` 那批只有 index.html 用。
🔴 **不分成 `js/` `css/`** —— 那是技术分层,与"按产品域拆"背道而驰,
而且 `common.css` 与 `common.js` 是同一件事的两半(拆开只会两处都要改)。

🔴 **`.html` 一律留在根目录,不进 `pages/`。**
`/stock.html?code=601857.XSHG` 是**外部书签与跨页链接的地址,属于产品契约**
—— 移进子目录会让所有旧书签 404,而"点了没反应"是最难查的那种坏
(同 backLink 那条)。selftest 里两向都钉住:`.html` 不许出现在子目录、
`.js`/`.css` 不许平铺在根(否则目录结构会慢慢退化,**而那不报错**)。
★ 服务端**一行没改** —— `os.path.join(WEB, rel)` + `startswith(WEB)` 防穿越
天然支持子目录。实测 `/shared/../../serve.py` 仍是 404。
🔴 selftest 里凡是扫 web 目录的地方**必须递归**(`_web_files`)——
`os.listdir` 只看一层,漏掉的文件其**所有组合都不参与比对**,
而那不报错,只是保护范围悄悄缩小(同"直接扫目录而不是照清单拼"那条)。

★ **index.html 按【产品域】拆,不按技术分层**(2026-09-04,3183 行 → 32 行)。
拆分点不是拍脑袋:先做依赖分析,发现**跨域调用几乎全是"路由 → 视图"这一个
方向**,反向只有 `enterView`/`stopPoll`/`modal`/`card`/`tab` 几个通用件 ——
那几个本来就属于骨架,顺手归位。`autoTag/autoBtn/autoNote` 也从 live 挪到
sync(它们是"自动同步开关",只有 sync 在用)。
★ **不引模块系统**:仍是裸的顶层函数 + `<script src>`。理由是 selftest 大量
用 `pg.evaluate('() => LV.can_backtest')` 直接读全局,包进 IIFE/模块就全断了;
而这个项目本来就是无构建、无 CDN 的单文件静态资源。
★ **hash 路由一行没动** —— 书签、深链接(`#/live/<id>/fills`)全部照旧。

**第二轮再拆**(同一天):`live.js` 与 `runs.js` 各按内部职责分开,边界仍然是
"用户在做什么"——
- `live.js` 照 CLAUDE.md 那张信息架构表分:**主视图(天天看)/ 三个浮层
  (偶尔用)/ 独立页(成交流水)** —— 表本来就写好了,照着切即可
- `runs.js` 分「**挑**哪一次回测」与「**看**这一次回测」

最大的文件从 3183 → 580 行。★ 记一笔与成交流水放同一个文件:它们是
同一件事的两头(录进去、查出来)。

🔴 **拆完组合数从 1 对变成 55 对** —— "跨文件顶层重名 = 整页 SyntaxError"
这条风险被放大了 55 倍,所以 selftest 里改成**两两全比**(原来只比
"每个页面 vs common.js")。命名约定:实盘 `LV`/`lv` 开头、回测 `RUNS`/`pane`
开头、同步 `SY` 开头。
★ 那条断言**直接扫目录**而不是照清单拼,且**数字自己算** ——
照清单拼会漏掉新文件的全部组合(而漏了不报错);数字写死的话下次再拆
就得手改,而"忘了改"的表现是报告串在说谎(它看着像验过了)。
🔴 **注释里别写连着的星号加斜杠** —— 拆分时我在 app.js 头部写了
"前缀 LV*" 加斜杠,那两个字符恰好把块注释提前结束,后面的中文成了裸代码,
**整个文件 SyntaxError**。`node --check` 当场抓到;不查的话表现是整页白屏。

### K 线读数：同一份信息只在一个地方看（2026-09-15）

用户三条，实质是**同一件事**：信息该出现在它该出现的地方。

| 要什么 | 原来 | 现在 |

| 框选读数 | 图**下面**一行小字（"太不明显"） | 贴在**选区外侧**的浮窗，涨跌幅打头大字 |

★ 但**只删不补是弄丢信息**：把它们从浮窗拿掉的同时，副图图例必须从

🔴 **只在不复权时画**：成交价是不复权实际价，切后复权标记会整体飘走

### 🔴 这一轮踩的三个坑，都是"看着正常"的那种

**① `X()` 返回的已经是 CSS 像素，不是 viewBox 坐标。**
我在框选浮窗的定位里又乘了一次 `width/1160`，算出 x=1522（视口才 1440）——
**被钳制兜住了，所以浮窗看着正常**。是写用例时鼠标移不到那个坐标才暴露的。
判据：`KGEO.X(最后一根)` 与画布 CSS 宽度比一比就知道该不该换算。

**② `geo` 是 `wire()` 的局部变量，`renderSel()` 在它外面。**
直接引用报 `ReferenceError`，而那**只在控制台里报**，浮窗照样弹出、
只是位置没算 —— 靠 `pageerror` 抓到的。改用模块级 `KGEO`（同 `LVSORT`
必须模块级那条）。

**③ 又一次在模板字符串的注释里写了反引号**，当场把模板闭合掉、整个文件
SyntaxError。CLAUDE.md 里记过（chart.js 那次），还是踩了。

### 🔴 判据选错了三次：像素量不出"图例有没有值"

「副图图例必须带值」这条我试了三个判据才对：

    ① 数图例带的像素     -> 只印名字也有像素，漏
    ② 量"最右像素 x"     -> 那条带子里混着 MACD 柱子与曲线，
                            两态扫出来**都是 1268**，完全被淹没
    ③ **拦 `fillText`**  -> 直接记下"画上去的文字"，一次就准

★ 教训：**画布上的东西，与其量像素不如拦绘制调用**。像素判据只在
  "有没有画"这种粗问题上可靠；问"画的是什么"就该去拦 API。
  而且拦 `fillText` 还顺带能验"跟随变化"（hover 到另一根，值必须不同）——
  只验"有数字"的话，写死一个常数也全绿。

## 🔴🔴 指标有【唯一正本】：`assay/indicators.py`（2026-09-15）

用户三条：「做一个各种指标的模块」「个股下按需展示，最多同时 4 个」
「买点也能按指标提示」。第一条是另外两条的前提。

改造前 MACD/KDJ/RSI/BOLL 的公式**写死在 `stock.indicators()` 里**，
而前端 `kchart.js` 又硬编码了一份「画哪几条线」与配色 —— 于是

    加一个指标要改【三处】：算的地方、接口、画的地方
    而漏掉画的那处**不报错** —— 只是选中它之后副图一片空白

现在一个指标 = 一条 `Spec`：**参数、算法、画哪几条线、什么样式、什么颜色、
预热多少根**全在一处声明；`/api/indicators/defs` 把它原样给前端，
**页面不认识任何一个指标名**（同「指标的中文标签/量纲在服务端」那条）。

| | |
|---|---|
| 主图叠加 | `ma`（均线）、`boll`（布林带） |
| 副图 | `macd` `kdj` `rsi` `atr` `cci` `wr` `obv` `bias` `spread`（均线差/金叉） |

🔴 **口径跟行情软件走，不跟教科书走** —— 对不上券商软件时，人会以为是
**数据错了**，而不会想到是口径不同：KDJ 用通用平滑（K = 2/3·前K + 1/3·RSV）
不是 SMA(3)；BOLL 的 σ 用**总体**标准差（除 N）；ATR/RSI 用 **Wilder** 递推。
selftest 里这三条各**手算一遍对数**（不是"看着差不多"）。

★ 等价性是量过的：改造前后拿 3 只票 × 3 种取法（区间/复权/翻页）比 JSON
  指纹，**9 组全同**；另有 2400 个值逐位比对。`git worktree` 检出旧版时
  **要指定 `ASSAY_DATALAKE`** —— 旧版按自己的路径解到 `/tmp/datalake`，
  两边跑的不是同一份数据，那不叫"验过了"（第一轮就这么翻车）。
★ 预热有个**下限 120 根**而不只是"按需要取"：RSI/ATR 这类 Wilder 递推
  **永远记着起点**，多喂 24 根末尾的值就会差几厘。下限是为了让默认那几个
  指标与改造前逐位一致 —— 少喂一点不报错，只是页面上的数悄悄变了。
★ `_ema` 从 `stock.py` 里**删干净**（只剩定义没人用的话，下次有人会以为
  它是正本）。

### 🔴🔴 指标选择器：**三版**才对，每版都是用户当场指出来的（2026-09-15）

    v1  工具条上平铺一排标签（一个指标一个）
        -> "指标数量上去后一横排也放不下"
    v2  一个按钮 + 竖排勾选面板（参数也在面板里）
        -> "点击指标会导致整个页面重新刷新"
        -> "修改指标的参数……每次点击导致页面高度、宽度变化，
            会影响整个页面的布局"
    v3  **副图 = 槽位**：默认两个，「+ 副图」加（最多 4），
        每个槽位**左上角一个下拉框**选显示什么，参数在**弹窗**里改

★ v3 才是行情软件的形态，而它带来一个结构性的好处：
  **成交量不再是画死的一块** —— 它就是第一个槽位的默认指标（`vol`），
  于是"把第一个副图换成 KDJ"这种事才做得到。
  🔴 `drawKChart` 里那块内置量能**整个删掉**，三个调用方（个股页 /
    浮层 / 广场）都改成传一个 `vol` 副图 —— 留着内置那份的话，
    "同一块画两处"迟早分叉。
  🔴 量柱是 `vbar` 样式：**按那天的涨跌上色**，不是按这个数的正负 ——
    成交量永远是正的，按正负上色整片都会是涨色（同 `upc` 那条）。
  ★ 涨跌停那个点原来钉在量能块下沿，现在改钉在**主图下沿** ——
    副图怎么换它都在。

**判据（各有各的构造条件，混在一起测全是空转）**：
| 要证的 | 怎么测 |
|---|---|
| 默认就是两个槽位 | `KINDS == ['vol','macd']` + `KGEO.nSub == 2` |

### 🔴🔴 买点按指标：把条件【反解成一个触发价】

用户要的是「距离 20 日线的距离」「MA5/MA20 金叉的距离」。

**直接报"现在离金叉还差 2.3%"是会骗人的** —— MA5 与 MA20 **两条都在动**，
那个百分比推不出"涨到多少就金叉"。所以档位存的是**条件**
（`{by:'ind', sig:'ma_cross', args:{fast:5,slow:20}, v:0}`），
而每次读时**反解出一个触发价**：「今天收在什么价位，这个条件刚好成立」。

于是指标买点与价格买点**落在同一个口径上**（都是一个目标价），
页面那套「到价 / 接近 / 还差多少」一行都不用改。

★ 反解用**二分**而不是解析式：解析式每加一个条件就要重推一次（MA 好推、
  BOLL 与 RSI 就很难），而二分只要求单调 —— 且单调性是**当场验**的
  （两端夹住 + 解完两侧必须翻面），不成立就明说"今天到不了 / 恒成立 /
  不单调"，**不猜一个数**。实测二分与解析解（金叉、距 MA20 都能手推）
  差 < 0.01，selftest 里两条都钉着。
🔴 **反解时 high/low 必须跟着收盘价改**：价格跌到触发价，那天的最低价
  至少是它。只改 close 的话 KDJ/WR/ATR 这些读 high/low 的指标会算出
  **今天不可能出现**的值（变异实测：K = −357、WR = 1500），而它不报错。
🔴 **方向不是都朝下**：价格档与「距均线 / 超卖」是**跌到**才算，
  而「金叉」是**涨上去**才成立。记反的话，一只已经金叉的票会显示成
  "还要涨 3%"，而它不报错。判据取 `op`（本模块所有序列都随当日价格单调增），
  页面按 `gap` 的正负说"还要涨/跌"。
🔴 **盘中要把实时价接到日线末尾再算**（`_bars_now`）：不接的话「距 20 日线」
  算的是**昨天**离昨天那根均线多远 —— 而这一页问的是"现在"。
  面板已经有今天了就**替换**最后一根，不再追加（否则同一天算成两天，
  均线的分母就错了）。
★ 日线**一次 SQL 取全部票**（`QUALIFY row_number()`）并按「面板最新日」
  缓存：这份数据每分钟轮询都要用，逐只查就是 N 次往返
  （同「抓取范围合并去重」）。只在**真有指标档时**才取。
★ 触发价一律用**不复权**：这一页的目标价是照着下单用的，而下单看的是
  券商软件里那个价（同 K 线默认不复权那条）。

### K 线：左右移动 + 框选测算区间（2026-09-14）

工具条最左边三个：「‹ 早」「晚 ›」「最新」，一步**半屏**（整屏跳的话两页

区间涨跌 / 最高 / 最低 / 振幅 / 天数 / 涨跌家数 / 量额。

🔴 **翻页按【根数】不按日期**（服务端 `off` = 跳过最新几根）：按日期翻要前端

🔴 **副图也要带 `off`** —— 不带的话翻页后 MACD 画的还是最新那一段，

🔴 **区间涨跌幅的基点取首根的【前收】**，不是它自己的收盘 —— 用首日收盘做

★ 选区存**索引**不是像素：换副图 / 换对数 / resize 之后重画，

#### 🔴 顺带修一个"选中即隐身"的老 bug

区间按钮写的是 `class="lvtag rg on"`，而 `.rg.on`（128 行，深字蓝底）与
`.lvtag.on`（385 行，蓝字透明底）**优先级完全相同**（都是 0,2,0）——
靠书写先后决胜负，于是后者把前者的 `color:#0f1216` 覆盖成 `var(--accent)`，
而背景还是 accent：**蓝字压蓝底，选中的那个按钮整个看不见**
（个股页的「1年」、对比页同样，实测 `color === backgroundColor`）。

★ 修法写成 `.lvtag.rg.on{color:#0f1216}`（0,3,0）—— **不依赖书写顺序**。
  靠"把 .rg.on 挪到后面"是定时炸弹：下次谁再加一条 `.lvtag.on` 之后的规则
  又会翻过来。
★ 判据**扫 6 个页面**、不是只看这一处：`.lvtag.on/.off/.rg.on` 的前景色
  一律不许等于背景色。这类"看不见"的元素在截图里像个纯色块，肉眼很容易
  当成设计。

🔴 **K 线柱子有【最大宽度】，画不满就往左贴，不要拉伸填满**（2026-09-14）

原来 `step = w / n` —— 有几根画几根、平分整个宽度。新股只有十几根时每根
就有 **60px 宽**（实测 688835 上市 15 天、画布 1334px），一屏几个大色块，
既看不出形态、也让人误以为"这只票就长这样"。

★ 判据用**单根最大像素宽**（`MAXSTEP = 14`）而不是写死"最少显示 N 天"：
  画布宽度本来就不一样（个股页 ~1334、浮层 1180），写死天数在窄画布上又太挤；
  "一根 K 线最宽 14px"在哪儿都成立，换算过来就是"最少 w/14 ≈ 95 天"。
🔴 **也不能反过来按"请求了多少天"留槽** —— 选「1 年」时 15 根票会被压成
  15 条发丝，那是另一个极端。人要看的是这只票，不是那个空窗口。
🔴 **往左贴而不是往右贴**：右贴意味着左边那片空白代表"上市之前"，
  而那些日子在 `bars` 里根本没有 —— x 轴标不出日期，等于画一段说不清是
  什么的留白。左贴时空白在右边，含义是"还没到的日子"，那是**自明**的。
★ 命中测试不受影响：两个调用点都有 `i < n` 的护栏。
★ 断言**两头都要钉**：只钉"新股不占满"的话，把 MAXSTEP 调成 1px 也全绿，
  而那会把所有图都压成左边一条 —— 正常股票必须**仍然占满**（实测老股
  250 根、每根 5.09px、占 99%）。3 条变异全抓到（含"贴错边"）。

    当日盈亏 = Σ 持仓批次 ×(现价 − 基准)      [今天买的用成交价，否则昨收]

|---|---|---|

再扣 `exit_fee_est` 就是 `pnl_net`(「全平落袋」),**不会重复计费**:

③ 「上传导出的包」→ 服务端 `merge_jq_increment.py --and-load`,把该跑的 loader

上传走**原始字节**(几十 MB 不该走 base64);文件名只接受 `[A-Za-z0-9._-]`、
只落到 `_ingest/downloads/`、**同名不覆盖加时间戳**(上传的包是原始凭据);

|---|---|
| 「策略」曲线 | 按**绑定版本快照**与当时参数、同本金、**账户自己的费率**，从开户日跑到今天的回测净值 |
| 「实际」曲线 | 现有的 TWR 净值 |
| 差异 | = **执行的代价**（漏单 / 价格 / 手工加减），**不是策略好坏** |

🔴 **两条的基点都必须是【本金】。** 头一版策略那条我取了 `tv[0]`（首日
**收盘**权益）—— 那等于把策略首日的涨跌排除在外，差异里混进「起点差」。
★ 而 froec 恰好 `tv[0] == cash`（周频、09-01 是周一空仓），所以这个错
**在当前数据上完全看不出来** —— 换一个首日就建仓的账户立刻是错的。
（与 CLAUDE.md 里「TWR 的起点是开户那一刻」修过的是同一个坑。）

🔴 **费率要用账户自己的**（`fee_model_at` + `effective_rates`）：引擎默认
万2.5/最低5元会让 froec 那种小额多笔凭空多付费用 —— 于是"策略曲线比实际差"
成了费率假设的产物。★ 三个接口形状我都猜错过一次：`fee_rates(aid)` 返回的是
**版本历史列表**（要 `fee_model_at`）、字段叫 `buy_rate`/`sell_rate`、
而 `sell_rate` **含印花税**（引擎 `Cost` 会按日期分段另加，直接拿它当
commission 等于印花税收两遍）。`Cost` 的参数也叫 `close_tax` 不是 `stamp_tax`。

🔴 **不归档。** 策略曲线是派生物：每天变、绑定版本一换就作废。塞进 `runs/`
会让「★ 选中的规则」与等价性回归里混进几百个一次性结果。落
`live/<id>/_bench/<key>.json`，键含 `data_fingerprint`（数据修正过必须重算），
**不入 git**（同 `signals/_explain/`）。

#### 🔴🔴 执行差异必须【按本金归一化】再比股数

实测 froec 的 2026-09-01：那份信号是按 **100 万**算的（账户后来改成 40 万），
实际投 37.75 万 —— 不归一化的话 10 只票里 **9 只被判成"买少了"**（实际都是
提示的约 38%），而那**根本不是执行差异**。归一化之后才露出真实的两条：
`300375` 提示外买入 9,100 股、`603381` 提示了没买。
★ 比例要**说在页面上**（`scale_why`），否则"要 9300 股、实买 3700"看着就是
没照做。★ 只在**比股数**时用这个比例；`extra`/`missed` 这种"有没有"的判定
不受它影响（买了没买是事实，与规模无关）。
★ 归属用**日期**（`trade_date == for_date`），不是"信号建好之后的第一笔"——
一天可能有多份 revision，而补录三个月前的成交也会被算进最近那期。

★ 页面上要说明**末尾那天策略常常没有值**：面板到昨天，而实际那条盘中会用
实时价多补一点 —— 不说的话看着像策略线断了。
🔴 三份数据是**并行**拉的（权益 / 策略 / 差异），所以渲染要在**两支**里都调：
头一版只在策略那支里写 `if(LPD) render...`，而它常常先回来、那时 `LPD` 还是
null，于是**执行差异块永远是空的**（数据在 `LPXD` 里躺着，且不报错）。

#### 🔴 「策略」与「实际」两条线的差异，有【结构性】来源 —— 不是执行失误

2026-09-10 用户问：「红利账户实盘的选择和策略应该是完全一致的，为什么 09-10
这天的涨幅会出现不一致」。逐层查下来（选股 -> 成交 -> 价格 -> 权重）：

**选股完全一致**（15 只一样）、**那天没有任何成交**、**价格也一样**。
差的是**每只的股数**：策略几乎每只都多买 **1 手**（11 只多 100 股、
1 只多 200 股、3 只相同）。于是

    持仓市值   策略 951,979   实盘 933,186
    现金       策略  41,932   实盘  61,570
    仓位       策略  95.78%   实盘  93.81%   <- 差 ~2pp

09-10 的日涨差就是这么来的：
`策略 0.3432% × 95.78% = +0.3287%` / `实盘 0.2314% × 93.81% = +0.2170%`。
★ 注意**持仓涨幅本身也不同**（0.3432% vs 0.2314%）—— 多买的那 1 手改变了
  各只的权重，而那天涨得多的几只（601009 +3.16%、601229 +2.09%、601328 +2.06%）
  恰好是策略多买了的。所以权重差在**涨跌分化大**的日子会被放大。

**为什么必然差这 1 手** —— 两个结构性约束，都无法靠"执行得更好"消除：

| | 回测 | 实盘 |
|---|---|---|
| 股数怎么定 | `lots = int(可用资金 / (**开盘价** × 100))` | `int(可用资金 / (**T-1 收盘 × 1.05**) / 100)` |
| 用到的信息 | **次日开盘价**（实盘那时还不存在） | 只有 T-1 收盘 |
| 资金占用 | 按成交额 | **挂限价冻结 `限价 × 股数`** |

实测 09-01 红利那期：可用 100 万，按昨收估的成交额 938,092，而**挂单要冻结
984,928（多 5.0%）、占可用资金 98.49%**，剩 15,072 凑不出一手。
也就是说 `twopass` 已经把 5% 缓冲算进去了 —— 它**必须**这样，否则券商拒单。
而开盘价普遍低于昨收（09-01 那天 15 只全部低开），回测就多凑出 1 手。

★ 用户指出的关键一点：**挂单后冻结的资金要等 09:25 成交才释放**，
  那时已经买完了 —— 想用释放的钱再多买一手，只能**盘中手工第二轮**，
  而那时不是竞价价了。

#### 🔴 降低 `PRICE_BUFFER`（1.05 -> 1.02/1.03）：**不值得**

冻结少 3% 能多凑约 1 手，但代价是**开盘超过限价就买不到**。
用两个策略**真实买过的票 + 那天**去数（不是全市场，那才是会挂单的场景）：

| 档位 | froec（858 笔建仓） | 红利（514 笔） |
|---|---|---|
| 开盘 > 昨收×1.02 | 17 笔 **1.98%** | 17 笔 **3.31%** |
| 开盘 > 昨收×1.03 | 8 笔 0.93% | 15 笔 **2.92%** |
| 开盘 > 昨收×1.05（现状） | 2 笔 0.23% | 7 笔 1.36% |
| 最大高开 | 1.0638 | **1.1002** |

★ **与直觉相反：红利（大盘股）高开的比例反而更高** —— 它买的银行/公用事业
  常有整体板块跳空（政策、分红行情），而 froec 每期 10 只小票、分散度更高。
🔴 **买不到的代价比多凑一手大**：漏一只 = 那期少 1/10~1/15 仓位，
  而多凑一手只值 ~1.9%。而且漏掉的**恰恰是高开的票**，那是有选择性偏差的
  （系统性漏掉"开盘就强势"的那批），不是随机漏。
🔴 **更根本的理由（用户指出）：后续"卖出再买入"的摩擦量级更大。**
  froec 年换手 10 次，光滑点 0.15% 双边就是 **1.5%/年**；而那 2pp 仓位差
  摊到全年收益不到 0.7pp，还要每个调仓日多操作一轮、多付一次最低佣金。
  **收益不确定、成本确定** —— 所以这个方向到此为止，`PRICE_BUFFER` 不动。

★ 结论：业绩页上那两条线**天然差约 2pp 仓位**，这不是执行失误。
  真要让它们可比，得让回测也按「T-1 收盘 ×1.05 冻结」算股数 ——
  但那会改变所有历史归档的结果，不值得为了对齐一条对照线去动它。

#### 🔴 策略线是【基准的一种】，与指数共用**一个单选槽**

头一版做成"常显 + 独立开关"，用户当场指出两个毛病：**颜色与上证撞了**
（都取了 `LPB_COL[0]` = `#7ec8a0`，两条一模一样时"哪条是策略"只能靠猜），
而且**关不掉**。而"想比哪个"因人而异、三条线以上就看不清了 ——
所以它就该和上证/中证500 那些并列，用同一套单选逻辑（同「默认一个都不勾」）。

现在：`LPB_STRAT = 'strat'` 与指数 code 存**同一个** `localStorage.lvbench`。
好处是"当前在比什么"只有一处状态，不会出现"既选了上证又开着策略"这种
要额外记的组合。策略色 `#b07de0` 不在 `LPB_COL` 的 9 个色里（selftest 静态
断言，改配色数组也能抓到）。
★ 拿不到策略曲线时（没绑定版本 / 快照缺文件）**不列这个选项** ——
  列出来点了什么都不出来比不给更糟（同 backLink 那条）。
★ 图下那段解释**跟着选中状态走**：没画线还留着一段话，读的人会去找那条
  不存在的线。
★ 那个没人读的旧开关 `LPSTRAT` **删干净**（连 localStorage key 一起）——
  留着下次有人以为它管事（同「删字段要连带清注释/配置/测试」那条）。

#### 🔴 顺带抓到：异步回调在【人已经走开】之后往 null 写

`renderChart` / `renderPerfTable` / `lprBar` 都是异步回调里跑的（权益要重放
整条曲线、策略曲线要跑一次回测），回来时页面可能已经切走 —— 那时容器是 null，
`null.innerHTML = ...` 直接抛。**它只在控制台里报，页面看着正常**，所以一直
没人发现；是新用例（先访问首页再进 perf 页）当场抓出来的。
★ 判据用**容器存在与否**，不是 `location.hash`：同一个 hash 下也会重渲染
  （换区间/换基准），而"容器在不在"是当下的事实。

### 🔴 涨跌配色：0 走中性色，且**只有一处定义**（2026-09-09）

## 🏭 行业板块页：三级下钻 + 选中后列表退成侧边栏（2026-09-29）

原来这一页是「一张申万一级榜 + 点一下在下面展开成分」。用户实测提了四件事，
每一件都**不报错**，只是看着像功能不全：

| 用户说的 | 真正的原因 | 判据落在哪 |
|---|---|---|
| 「只展示了 10 个，没有展示全」 | 31 个**全在 DOM 里** —— 是那个 `max-height:420px` 的小滚动框把后面的截在视野外，边缘又没有任何"下面还有"的提示 | 不是"DOM 里有几行"（那一直对），是**滚动区高度 / 视口 >= 0.6** + 表尾写明「共 N 个，到底了」 |
| 「点行业里的银行I，不是成分股，而是到了另一个面板」 | 链接传的是 `?code=`，新页面的选中状态在 `path` 里，`code` 被忽略 -> 落回全表 | 反查一次列表把 `code` 还原成 `path`；**反查不到不静默落回全表**，把原因写在页面上 |
| 「点击板块时整个页面跳动」 | 每次 `load()` 把 `#pg` 整块 `innerHTML` 重渲染 —— 滚动位置归零、布局闪 | **同一个 DOM 节点还在不在**（`===` 比对 `.secwrap` / `#secmain`），不是截图像不像 |
| 「平均涨幅、中位可以排序」 | 只有后端一种固定序 | 点表头后**榜首换了谁**，且期望从**另一条路**算（自己问一次接口再自己排），不拿页面的输出当期望 |

### 布局：两种状态，信息密度不一样

- **没选中** —— 板块榜撑满视口（加权/等权/中位/家数/涨跌/涨停/成交额/领涨股），
  表头 `position:sticky` 吸顶，整屏滚动。这时人在**比较**，要宽表。
- **选中后** —— 左边退成 190px 侧边栏，**只留板块名 + 涨跌幅**；右边是内容。
  这时人在**看细节**，侧栏只负责"换一个看看"。

🔴 **侧栏列的是【同级兄弟】，不是子级** —— 子级在右栏。这样"换一个行业"
只要一次点击；列子级的话每换一个行业都要先退回上一层。

### 只换内容，不重建外框

```js
function shell() {            // 外框只建一次
  if ($('#secmain')) return;
  pg.innerHTML = '…#sechead…#seccrumb…<div class="secwrap"><div id="secside">…<div id="secmain">…';
  pg.addEventListener('click', onClick);   // 委托在稳定容器上，只绑一次
}
function setHtml(sel, html) { // 内容真的变了才写 DOM
  const e = document.querySelector(sel);
  if (e && e.innerHTML !== html) e.innerHTML = html;
}
```

★ 事件**委托在 `#pg` 上**：下面几块每次都换 innerHTML，绑在元素上的
`onclick` 换一次就没了（同「innerHTML 填充之后才存在的元素要重新绑事件」）。

### 层级

`SW_NEXT = {sw:'sw_l2', sw_l2:'sw_l3', sw_l3:null}`。停在一级 -> 右栏默认列
下属二级排行；停在二级 -> 三级；停在三级 -> 成分股。任何一级都能切「成分股」页签。
🔴 **通达信那几类（概念/风格/地区/研究）只有一层，不出层级页签** ——
强行造两层只会多一次空点击（用户原话：「只有一层没必要强行搞两层」）。

### URL 要带住【整条路径】

```
?kind=sw&path=[{kind,code,name},{…}]&tab=mem&sort=amount&asc=1&date=…
```

🔴 只存最后一级的话，刷新/分享/后退会丢掉"我是从哪一级下来的"，面包屑就断了
—— **而页面看着完全正常**。
🔴 **判据必须「先点再刷新」**：直接拿一个手写 URL 进去，测的是"页面读得懂
URL"，漏掉的那一半正是"`nav()` 有没有把整条路径写进去"。变异 M11（只存
最后一级）就是这么漏网的，改成点两级再 `goto(pg.url)` 才抓到。

### 口径

涨跌幅主列用**流通市值加权**（申万行业指数、东财/同花顺板块涨幅同口径），
等权与中位并列 —— 2026-09-28 石油石化加权 +1.66% 而等权 −0.62%，
前者说"这个板块的钱涨没涨"，后者说"里面多数票怎么样"，**常常不同向**。

排序时空值一律沉底（**不猜一个 0** —— 那会让"没有数据"的板块混进榜首/榜尾，
看着像真的）。
