# 架构与拆分 —— 踩坑详情

正本索引在 `assay/CLAUDE.md`。**拆文件、抽正本之前**读这一册；里面每一节都是实测定案（有现场、有判据、有变异结果）。

## 服务端与实盘模块也按【产品域】拆(`assay/srv/` 与 `assay/lv/`)

```
assay/
  server.py   243 行【骨架】：ROUTES/POSTS + Handler + serve() + 对外门面
  srv/
    base.py   可变模块级状态 + 被【2 个以上域】调用的通用件
    runs.py  docs.py  live.py  rt.py  sync.py  stock.py  market.py  watch.py
```

★ 切点是**两轮客观分析**的结果(2026-09-04,2558 行 → 243):
作者原有的 `# ==== ====` 段落标记给出 9 个域;再取「被 2 个以上段调用」的
定义(12 个)+ 传递闭包(只多带出 `_current_fp` 一个)进 `base.py`。
依赖是单向的:`server → srv.* → srv.base`;`srv/live.py` 与 `srv/watch.py`
单向依赖 `srv/rt.py`(`_rt_ensure`),反向调用一律走 base 里的延迟导入封装
(`_live` / `_rt` / `_watch` / `_alerts` / `_market`)—— **循环由此断开**。

🔴 **搬运代码进子目录有三个坑,全都【不报错】,实测全踩了一遍:**

| 坑 | 表现 |
|---|---|
| **`__file__` 深了一层** | `HERE = dirname(__file__)` 变成 `.../assay/srv`,于是 `picks.json`/`live/`/`web/` 全解到不存在的路径。**实测:`/api/marks` 返回 `{}`(标记全丢)、7 个实盘接口 500** |
| **相对导入的 `.` 也跟着变** | base 里 `from . import live` 原本是 `assay.live`,搬进 `srv/` 后 `.` = `assay.srv` → 返回**路由模块自己** → `m.LiveError` AttributeError |
| **留在别处的【变量】** | 拆分脚本按 `NAME(` 替换调用,漏了 `_DATE_RE` 这种变量和 `Thread(target=_run_job)` 这种传递。**import 成功、45 个 GET 全对**,因为那几行只在 POST 分支走到 |
| 🔴 **名字遮蔽** | `serve()` 里 `rt = base._rt()` 建了个局部变量(业务模块 `assay.realtime`),把模块级 `from .srv import ... rt`(路由模块)**遮蔽**掉 → `rt._RT` / `rt._rt_loop` 去 `assay.realtime` 找 → AttributeError。**「未定义名字检测」抓不到它**(名字是定义的,只是指向错的对象) |

🔴🔴 **最贵的教训是【验证的漏洞】,不是这几个坑本身。**
我全程用 `python3 serve.py --readonly` 验证 —— 而 `--readonly` **不走
`ALLOW_LIVE` 那个分支**(起实盘线程 + 行情线程那段)。于是那几行代码
**一次都没执行到**,45 个 GET + 16 个 POST + 54 项等价性全绿,
直到用户真的敲 `python3 serve.py` 才在启动时崩掉。
★ 所以拆完必须**两种模式各起一次**:`--readonly` 与不带参数(全功能)。
现在 selftest 里钉了两条:通用的**名字遮蔽检测**,
以及 `serve()` 全功能分支引用的名字(`rt._RT` / `rt._rt_loop` /
`live._live_loop`)必须真的存在。

★ 所以验证**不能靠"启动不报错"或"接口打得通"**。做法是三层:
① `git worktree add --detach /tmp/assay_old HEAD` 起旧版,**逐个路由对比响应**
(45 GET + 16 POST);② 静态扫每个模块里 **Load 但未绑定的名字**(那三个变量就是
这么抓到的);③ selftest 里把三个坑各钉一条断言 + 变异测试。
🔴 对比时先做一次**同服务连打两次**的自证 —— 盘面/板块三个接口两版**自己就不稳定**
(含实时成分),不先自证会把它们当成拆分引入的差异去查。

🔴 **对外门面必须是 `ModuleType` 子类,不能只用 PEP 562 的模块级 `__getattr__`。**
`assay.server` 是对外契约(selftest 用 28 个 `sv.*` 名字),其中
`ALLOW_BACKTEST`/`ALLOW_LIVE` 是 **serve() 会重新赋值的 bool**,而外部也会
写它(selftest 26 处 `sv.ALLOW_LIVE = True` 模拟启动模式)。
`__getattr__` **只拦读**:一旦有人赋值,就在 server 的 `__dict__` 里建了副本,
之后读取走正常查找、不再转发 —— 各域读到的还是 base 里的旧值,
**「设置了却不生效」**。实测这么挂掉 3 个用例。所以真值只有一份(在 base),
`__setattr__` 把白名单里那几个名字**写回 base**。
★ 白名单只放"会被外部重新赋值"的;`ROUTES` 这种本模块自己的定义不能转走。
★ dict/list 那些**原地修改**的容器(`_index`/`_cache`/`_RT`)没这个问题,
可以直接 `from .base import`。

两个循环(`base ↔ fee`、`fill ↔ pos`)只靠**挪两处归属**就消掉了:

把写操作重定向掉、不污染真实账本(那条纪律的实现手段)。而读取方

`lv/base.py` —— 门面若是 re-export,**重定向静默失效,用例会把数据写进
`live/` 真账本**。变异测试演示得很清楚:

```

base.LIVE     = <repo>/live                        ← 没跟着变
acct_dir("x") = <repo>/live/x                      ← 🔴 还在写真账本
```

所以门面同样是 `ModuleType` 子类,`_FWD = ('LIVE',)`。
★ 验证的最终判据是**跑完 selftest 后 `git status live/` 必须干净**。

### 🔴 又一个坑:`ast` 的 `col_offset` 是 **UTF-8 字节偏移**

跨域引用要加 `_域.` 前缀,我用 ast 定位精确位置来改(比正则可靠 ——
正则按 `NAME(` 只匹配调用形式,会漏掉变量引用和 `Thread(target=fn)`)。
但 `col_offset` 是**字节**偏移,而 Python 字符串索引是**字符**:
含中文的行上(`raise LiveError('mode 只能是 %s' % '/'.join(FEE_MODES))`),
同一行第二个替换就错位,被我那个 `if s[col:col+len(nm)] == nm` 的保护分支
**静默跳过**了。改成按 `line.encode('utf-8')` 做字节级替换才对。
★ 教训有两条:**保护分支不该静默跳过**(该 assert),
以及**光有"未定义名字检测"能兜住它** —— 那 4 个漏掉的名字就是它抓出来的。

### ② datalake 根与面板读法：`assay/paths.py`

🔴 **8 处各自数 `dirname` 层数**，而层数是跟着「这个文件放在哪」变的。
`lv/px.py` 里那句注释就是物证：「`__file__` 在 `lv/` 里比原来深一层，
所以要多剥一层 dirname」—— **搬一次文件就要改一次，而改漏了不报错**，

返回 `{}`、7 个实盘接口 500）。`paths.py` 位置固定，层数只数一次。

🔴 面板的 `read_parquet(...)` 同样 8 处各拼一遍，而 **`lv/intraday.py` 拼的
glob 是另一个**（`panel_daily/**/*.parquet` 而不是 `panel_*.parquet`）。
今天两者恰好同 24 个文件、同 1631 万行（量过），所以一直看不出来 ——
但 `**` 会把 `panel_daily/` 下**任何**子目录里的 parquet 也读进来。
★ 以 `feed.PanelFeed` 为准（引擎那条路的权威）。
🔴 **`feed.FINGERPRINT_PARTS` 盯的必须与实际读的是同一批**：指纹盯的少一个，
  就会出现「数据变了而指纹没变」，于是 tick 判「不用重算」、模拟盘判
  「不用推进」，**两个都不报错**。所以两边取同一个 `PANEL_GLOB` 常量。
  ★ 第一版我用 `panel_sql('').split("'")[1]` 去抠那个 glob —— 它回落成了
    **绝对路径**，指纹当场从 `9b928ed9838f` 变成 `26a9193ec7d4`。
    导出一个常量才对。修完指纹回到 `9b928ed9838f`，与 16:19 那份真实信号里
    记的逐位相同。
★ **异常没有收进正本**：CLI 要 `SystemExit`、HTTP 要 `LiveError`、看盘要
  `StockError` —— 那是各自的 UX，混成一个反而让报错指不到地方。
  正本只回答"路径是哪个"。

### ③④ 万/亿折算与盈亏符号：`common.js` 的 `yiv` / `pnlv`

同一个 13,844,147 在四个页面长成 `1384.4万` / `1384.4万` / `1384万` /
`1384 万` —— 同「名称+代码那一格全站一处定义 `cnCell`」那条。

`live-perf.js` 还有**两个同名 `money`**（不同函数作用域，所以不是
SyntaxError），行为却不同：图里那个**没有 null 守卫**，而 `null >= 0`
在 JS 里是 **true** —— 实测吐出 `+— 元`；两个都用 `>= 0`，
于是**平盘写成 `+0`**，等于凭空报了个赚（同 `upc` 那条「判据要
`> 0` / `< 0` 两头夹」）。

★ `yiv(v, o)`：**阈值 / 单位 / 空格一份，小数位仍由调用方给**
  （y 轴要短、tooltip 要精确、成交量轴另有分档，传函数就能按量级挑）——
  变的只是精度。
⚠ `stockpop.js` 的「总市值 … 亿」「量 … 万股」**不在此列**：那是**固定单位**
  不是按量级挑单位；`live-fee.js` 那一堆 `*1e4` 是**万分率**。
  判据因此必须精确到 `>= 1e4/1e8` 这个写法 —— 见 `1e8` 就拦会误伤两类
  （同「判据比要证的事宽」）。
🔴 **对数当场抓到一处我自己引入的回归**：第一版 `pnlv` 用了 `Math.round`，
  而它**一律朝 +∞**（`Math.round(-99.5)` 是 **−99**），于是 +99.5 与 −99.5
  朝同一个方向舍。改回交给 `num`（`toLocaleString`，对称）。
★ 对数口径：53 个真实数值**逐位一致**，只有 NaN / ±Infinity / 空串 从
  「NaN」「Infinity亿」「崩」变成「—」；`live-perf` 两处另有 `0` -> `0`
  与 `null` -> `—`。**都是修，不是精度漂移**。

### 三条"没修好的"后来都修了（2026-09-21 收尾）

#### ①🔴🔴 偶发红的根因是**产品 bug**：「hash 指向 A、页面显示 B」

上一轮只给那条 web 用例加了"带现场的断言"，没定位根因。这次让它
**跑 60 轮**，现场把它钉死了 —— 12 轮失败（20%），**每一次都是**

    hash='#/live/hongli'   h2/LVSEL='a6'   LVGEN=5   页面报错=[]

路由那一发取了较小的代际先 `await`，而**建完账户那条非路由的路**随后又调
`showLive(a6)`、取到更大的代际先回来渲染；路由那一发回来时
`gen !== LVGEN`，**按设计作废了自己**。

🔴 根因是**「页面显示哪个账户」有两个真值**：hash，和"谁最后回来"。
  代际守卫只解决了"旧的别盖新的"，解决不了"新的是不是人要的那个"
  （同「判据永远是现在的状态，不是记录」）。

修法（真值只留 hash）：`lvStale(gen, aid)` —— **hash 点名了具体账户时
只有它算数**，hash 没点名（`#/live` 列表页）才退回比代际；建完账户
**走 hash** 而不是 `showLive`，**且只在人没自己走开时跳**。

★ 那个"只在人没走开时跳"不是多余的谨慎：无条件跳会把竞态**从"渲染"
  搬到"导航"** —— 实测现场从 `hash=hongli 显示 a6` 变成了
  `hash 被顶回 a6`。**修一处竞态最容易引入的就是它的镜像。**

失败率 **12/60 (20%) -> 3/40 (7.5%) -> 0/40**。

⚠ 剩下那 7.5% 是另一回事，如实记：`#nf_paper .nn` 等满 20 秒也不出现 ——
  不是慢，是**那一下点空了**（侧栏整块 innerHTML 重渲染，点击落在将被
  替换掉的 DOM 上，按钮连同 handler 一起没了）。
  **这既是测试太快、也是真实的产品隐患** —— 真实用户在那一瞬点
  「+ 新建」同样会没反应。这里只让 helper 认得出并重来一次，
  **没有修产品**：那要动"侧栏不必要的整块重渲染"，是另一轮的事。
  ★ 而且只给"开表单"加重试**不够**，实测挂在 `pg.fill` 上（表单在
    打开之后、填之前被换掉）—— 开 + 填 + 提交要**一起**重试。

★ 判据：并发那条用例补了**第三、第四两段构造**，都是前两段测不到的 ——
  前两段两发都改了 hash，于是"最新那发"与"hash 要的那发"恰好是同一个，
  **纯代际判据就够了，测不出区别**。

  重渲染，漏进来的话按钮解析得到却**点不动**，报的是裸超时。

## 🔴🔴 代码路由：ETF 与股票的代码同形，入口必须自动判（2026-09-30）

用户：「etf 和股票的代码既然完全一样，那应该在调用入口处统一一下，比如做一个
编码的路由表，自动根据编码识别是 etf 还是股票，调用对应的数据。只要指定传入是
ETF 还是股票时，才只从对应的池里面获取数据。」

### 先量前提，再谈设计

`510300.XSHG`（ETF）与 `600000.XSHG`（股票）**肉眼无法区分**，所以调用方
判不了。而实测两个池的代码**交集是 0**（主面板 5546 只 / etf_lake 3430 只）
—— 所以「代码 -> 属于哪个池」是**唯一确定**的。
**自动路由不是启发式，是可证的。** 这条是前提，不是附带检查：
真重叠了，整套路由的依据就没了，所以守卫把它当第一条断言。

### 路由表早就有，缺的是覆盖面和「显式指定」

`assay/symbols.py:kind_of()` 已经在做这件事，判据是**快照里的 class**，
不按代码前缀猜 —— 前缀规则是会变的（科创 688、北交 8 开头都出现过）。
实测六个 `/api/stock/*` 入口对 ETF 都已经路由对了。

但有两个真缺口：

**① 路由表盖不住已停止交易的（1104 只）。** 快照 `symbol_name` 只收
**当前在市**的标的，而 `etf_lake` 特意保留了已清盘的 1796 只（保留它们才
没有幸存者偏差）。于是 3430 只里 **1104 只被判成"股票"** -> 去主面板找 ->
主面板一行都没有 -> 「取不到日线」，而它明明有完整历史。
那 1104 只**全部**都在 tdx 的 `etf_*` 日线文件里。

修法：来源改成「快照的 class ∪ 日线文件里实际有的 symbol」，快照优先。
路由表 3048 -> **4899** 条，etf_lake 判不出来的 **1104 -> 0**，
而主面板 5546 只股票 **0 误判**（反向自证）。
代价：首次 0.005s -> 0.013s（symbol 是字典编码列，DISTINCT 很便宜），
二次走缓存 0.0004s。缓存键**同时**带快照路径与日线文件的 mtime ——
只按快照缓存的话，新上市的 ETF 要等快照换文件才认得出。

**② 没有「显式指定」。** 新增 `symbols.route(code, root, kind)`：

    kind=None（默认）  自动判
    kind='stock'       只当股票；是 ETF/指数就抛 KindMismatch
    kind='etf'/'index' 只从那个池取；不在就抛

🔴 **指定了就不许回落。** 回落等于"指定了却没生效"，拿到的是另一个池的数
而**看着完全正常**。对外用 `'stock'` 而不是 `None`：URL 上 `kind=` 空着与
"没传"分不开，而这两件事完全不同。
🔴 反过来，**不指定时必须自动判** —— 靠调用方每次记得传的都会漏。

`?kind=` 接进六个 `/api/stock/*` 入口。`KindMismatch` 不是 `StockError`
（`symbols` 在 `stk` 之下，继承会绕成环），所以 `_stock_err` 要**显式接住**
—— 接不住就是 HTTP 500，而 500 指不到"你指定的池和这个代码对不上"。

### 这一轮的三条教训

**「用了 `kind` 却没收」会当场 NameError，而它只在传了 kind 时才犯。**
改签名时正则漏了 `finance(code, n=16, root=None)`，函数体已经用上 `kind`
了 —— 不传时一切正常，传了才炸。守卫按 ast 扫全仓：函数体里读 `kind`、
参数里没有、体内也没赋值过，一律报。

**写了补丁却没执行。** 那条命令只 `cat > file` 然后就去 grep 了，
输出里没有 `patched` 那一行而我没注意 —— 于是拿着"没改过的代码"量了一轮，
结论全错。**判据永远是现在磁盘上是什么**，而"我写了"不等于"跑了"。

**三条变异不成立，各有各的不成立法**，都不能算"漏了"：

| 变异 | 为什么不成立 |
|---|---|
| 日线覆盖快照（顺序反过来） | 两个来源对同一 symbol **零分歧**，两种写法可观察行为完全相同 |
| 构造一条分歧来测「分歧要报出来」 | 我变异的是 `_kind_map`，而那条断言自己直接查快照 —— 两者不相干 |
| 「`'KindMismatch' in body`」这条断言 | 它是**字符串出现过**：把 `except` 里那一项删掉、import 行还留着，照样绿。改成真调一次接口才抓到 |

★ 「零分歧」本身值得钉住：真分歧了「谁优先」怎么定都是猜，该报出来让人
  决定（同「对账不一致要报出来、不改写」）。它的反向自证不是改代码，
  是**注入一条假记录**确认那段逻辑会报 —— 注入后当场给出
  `('sh510300', 'index', 'etf')`。
